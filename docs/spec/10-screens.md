## 1. 共通(ヘッダー・フッター・ナビ)

- ヘッダー(`glass_ops_camera.png` 上部): 左に `RGCS`、メンテナンス中は縦罫 + 「メンテナンス」。機体数(Copter / Rover / 警告)。中央にナビ 6 ボタン(運用マップ / 全機体映像 / ミッション / ネットワーク / AI チャット / メンテナンス・設定、`.seg.n6` 344px、アイコンは 20 §9)。右にログインユーザー名、時計、メンテ中は閉じる。 6 ボタンとも有効(AI チャットは 2026-10-24 から。押すと運用マップの右パネルに AI を開閉する、§3.4)。
- ユーザー名クリック → ポップオーバー(`.pop`): ユーザー名、役割「オペレータ」、注記「操作履歴にはこの名前で記録されます」、「ログアウト」。
- フッター(`glass_ops_2d.png` 下部): 中央のログピル(幅 `min(620px, 可視幅)`)。先頭「全体」(メンテ中は無し)、**最新 1 件**(重要度アイコン・時刻・発生元・本文)、**未読の警告・エラー件数バッジ**(アンバー、`.newbadge`)、開閉の山形、時計。ピル全体がボタン。
- メッセージ履歴シート(`.logsheet`、`glass_ops_log.png`): ピルの上に開く `g-strong` シート。見出し + 件数、絞り込みセグメント(すべて / 警告・エラー / 機体名 — 機体のメッセージ欄から開いたときだけ)、新しい順のスクロール一覧(重要度アイコン・時刻・発生元(機体名またはシステム)・本文。警告・エラーは太字)、注記「直近 500 件を表示。それ以前はメンテナンス › ログ」。開くと未読数を 0 にする。メッセージが溜まってもピルは 1 行のまま。
- 重要度: `info` / `ok` / `warn` / `error`。アイコン info / circle-check / triangle-alert / octagon-x、色 `--text-2` / `--ok` / `--caution` / `--danger`(`.sev-*`)。STATUSTEXT の severity 0–3 = error、4 = warn、5–7 = info、成功した `command_result` = ok。
- 言語: ja / en。切替はログイン画面とアプリ設定。`I18N[lang]` 相当の辞書で UI 文言を持ち、機体由来の文字列(モード名、STATUSTEXT)は原文のまま。
- 未ログイン時はヘッダー・フッター・各画面を描画しない(`authed` ゲート)。

受け入れ条件: ナビの現在位置がレンズで示される。ログアウト後は `/api/*` が 401 になり、UI はログイン画面に戻る。

## 2. ログイン(`glass_login.png`)

- 全面 `--base` + `.aurora`。中央に `g-strong` カード(幅 400)。
- 内容: `RGCS` + 「開発用」バッジ(モック認証が有効なときだけ)、接続先ホスト名(サーバーが返す `hostname`)、ユーザー名、パスワード、「ログイン」(Enter でも送信)、エラー行、言語セグメント、注記「開発用アカウント admin / admin」(モック時のみ)。
- 失敗時: 「ユーザー名またはパスワードが違います」を `--danger` で表示。入力を変更すると消える。5 回失敗で 60 秒ロック(サーバー側、`429` を「しばらく待ってから再試行してください」で表示)。
- 成功時: セッションクッキーを受け取り運用マップへ。以後の送信操作は全てこのユーザー名で `audit_log` に記録される。
- プロトタイプとの差: 「オペレータ登録」モーダルは廃止。

受け入れ条件: admin/admin でログインできる。誤入力でエラー行。ログアウトで戻る。リロードしてもセッションが続く。

## 3. 運用マップ(`view:'ops'`)

### 3.1 地図
- MapLibre GL。2D / 3D セグメント(3D = pitch 60、bearing −25、地形 DEM)。コンパス、スケール、帰属(ホバーで展開)。
- 3D の機体モデル(2026-10-22): Copter / QuadPlane / 固定翼 / Rover の 4 種類。QuadPlane はブームに 4 ローターと尾部の推進プロペラ、固定翼は機首のプロペラだけ。QuadPlane の HEARTBEAT は FIXED_WING なので、`VehicleState.vtol`(`EXTENDED_SYS_STATE.vtol_state`、30 §テレメトリ)で区別する。
- **レイヤー順**(下から、プロトタイプ `orderLayers()`): 背景 → 衛星画像 → DSM 陰影(`hillshade`、地形とは別ソース)→ 地名ラベル → ミッション経路(運用マップでは計画中ミッションを細線で)→ 飛行の軌跡(選択機はアンバー、他はアクセント、破線)→ 機体まわりの線(Guided の目標線、視線、3D の高度ポスト、カメラの四角錐)→ 機体マーカー(DOM、常に最前面)。
- **機体マーカー**(`.rg-mk` > `.vmk`、`glass_ops_2d.png`): 白縁 2px の円(30px、Copter = `--accent`、Rover = 白、選択 = `--caution` + 外輪)に種別アイコン(Copter = drone、Rover = car)。縁に機首方位の三角(`.hd`、`.arrow` ごと機首方位へ回転、暗いドロップシャドウ)。名前ラベルは濃い不透明ピル。ホームは機体と別の白い角丸マーカー(`.rg-home`、house)。WP・ROI マーカーにも白縁を付け、明るい地図でも見えるようにする。
- **視線(`sight`)**: 2D のみ。選択機からジンバル方位(機首方位 − ジンバルヨー)へ、ROI 追従中は目標まで / それ以外は 450 m、緑の破線 + 暗い縁取り。**ROI プリセットマーカー**(`.rg-roi`、名前付きプリセットのみ、追従中はリング)。
- **撮影方向**(ジンバル角を持つ機体だけ、計算は 40 §7.2): 2D は機体マーカーから緑の扇(`.fov`、選択機は濃く)。3D は機体の空中位置から四角錐 + 先端の半透明の面(`glass_ops_3d_gimbal.png`)。アプリ設定「ジンバルを地面に投影」が有効なら、2D・3D とも視野が DSM と交わる範囲を地面に塗る(`glass_ops_3d_gimbal_projected.png` / `glass_ops_2d_gimbal_projected.png`)。3D では 2D の扇と視線は出さない。
- 3D では機体を高度で浮かせ、地表から引出線(`AirPathLayer` の仕組みを流用)。
- 追従(機体リストの照準ボタン): 地図中心を機体に追従、上部中央に「追従中 UAV-xx ✕」チップ。地図を手でドラッグすると解除。
- パネルの幅に応じて `setPadding` を同期し、追従・移動が可視領域の中央になる。

- **進路と目標**(P8、2026-10-19、2D のみ。3D は 3D 地図と合わせて後日): 対地進路(GLOBAL_POSITION_INT の vx/vy、0.5 m/s 以上)を機体から実線で描く。長さは 10 s 先の位置で、画面上の最低 70 px。選択機は白に暗い縁取り、他機は `--accent`。AUTO / GUIDED / RTL / SMART_RTL / LAND / BRAKE でアーム中かつ NAV_CONTROLLER_OUTPUT の `wp_dist > 0` のときは、目標方位・距離の点まで破線を引き、点を打つ(選択機 `--caution`)。POSITION_TARGET_GLOBAL_INT の点は、その位置と 25 m 以内で一致するときだけ使う。
- **ホーム**: HOME_POSITION があればそれを、なければ機体が持つミッションのホームを `.rg-home` で出す。
- **選択中の機体**(P8): `.vmk` に四隅のブラケット(`.lock`、`--caution`、選択時に縮みながら現れる)と、広がって消えるビーコン(`.beacon`、1.8 s 周期)。`prefers-reduced-motion` では静止。
- **マップタイプ**(P8): 地図右上(`map-r top1`、ミッション画面は 2D/3D の下 `top2`)の `Layers` ボタンから選ぶ。候補はサーバーの `[[basemaps]]`、未設定なら 地図(`map_tile_url`)/ 衛星写真(Esri + Carto ラベル)/ 地理院 標準 / 地理院 写真。選択はブラウザごと(`localStorage` `rgcs.basemap`)。
- **WP へ行く**(2026-10-21): 運用マップのミッション番号バッジ(2D・3D)を押すと、バッジの位置に小さなポップオーバー「WP {n} へ行く」(機体名、AUTO 以外なら「AUTO 以外では、次に AUTO にしたときこの WP から進みます」、送信 / キャンセル)。送信は `MAV_CMD_DO_SET_MISSION_CURRENT`(224、param1 = バッジ番号 = MAVLink seq)を `other` で送り、モードは変えない。通信断・機体不明では送信不可。Esc・外側クリック・ズーム・操作者が始めた地図の移動 / 回転 / 傾け(3D を含む。追従による移動は除く)で閉じる。画面端では画面内に収め(下に余地が無ければバッジの上に開く)、送信を隠さない。結果はログに「WP へ移動」で出る。

### 3.2 機体リスト(左 296px、折りたたみで 60px レール)
- 検索(名前・モード)。行: 種別アイコン、ドット(警告=アンバー、Copter=アクセント、Rover=白)、名前、モードバッジ、バッテリー(50% 未満はアンバー)、高度、速度、通信強度、追従ボタン。
- 選択行はアクセントのティント + 枠。クリックで右パネル(詳細)を開く。

### 3.3 右パネル 詳細(372px、`glass_ops_camera.png`)
1. ヘッダー: ドット、機体名、ピン(常に表示)、閉じる。ピン(2026-10-20): 押すとパネルをこの機体に固定し、地図やリストで別の機体を選んでも(選択の強調は移る)パネルと全コマンドはこの機体のまま。もう一度で解除、閉じるでも解除。固定中の機体が消えたら選択中の機体に戻る。
2. 映像サムネイル(16:9): AUTO REC ピル(録画時間)、最大化ボタン。映像未接続は「映像未接続」。
3. **カメラ帯**(カメラ割当あり): 録画トグル(ON は `--rec` 塗り、点滅ドット)、写真、ズーム(`.zstep`: − / `.big` 倍率(最小幅 64px)/ +、アイコンボタン、1 段)、歯車(カメラ設定)。1 行に収める(最大 165× でも重ならない)。映像タイプ(RGB / IR / 2画面; サーマル能力があるときだけ)はサムネイル左下に重ねる(`.seg.n3.sm.onmap`)。
4. **カメラ状態行**: 髪線区切りで「ジンバルモード | ↔ ヨー ↕ ピッチ | ROI 名 | 追跡中 / 見失い」。MAVLink カメラは「MAVLink カメラ | ↔ ヨー ↕ ピッチ」(モードの代わりに種別名。2026-10-23、40 §2)。カメラ未設定は「カメラ未設定 | 設定する」。
5. テレメトリ 3 列: 高度、速度、バッテリー(`.big`)。
6. タイル 3 つ(アイコン + 短いラベル、高さ 64): メンテナンス(この機体のメンテナンス・設定へ。校正の最後が失敗か 30 日超ならアンバーの点)、履歴(この機体に絞ったメッセージ履歴シート。確認待ちの件数を角に)、全コマンド(シート、開いている間は `.on`)。
7. 計器(2026-10-21): メッセージの上に丸い計器 2 つを横に並べる。姿勢指示器(空 / 地面の円盤をロールで回しピッチでずらす。ピッチ目盛 10° ごと ±30°、固定の機体記号、ロール目盛 0/10/20/30/45/60° とポインター)とコンパス(N/E/S/W・30° 目盛の回転カード、上の固定線が機首方位、対地進路があれば小さな印)。下に数値行 `R −12°  P +4°   HDG 087°`。姿勢・方位が無ければ薄く表示し値は「—」。 コンパス中央の機体記号は機体の種類ごと(2026-10-22: Copter = X 型 4 ローター、QuadPlane = 固定翼 + ブーム + 4 ローター、固定翼、Rover = 4 輪。3D モデルと同じ選び方)。
8. メッセージ: 選択機の 1 件(重要度アイコン・時刻・題名・本文)。確認待ちの警告・エラーがあればその最新の 1 件(確認ボタン付き)、無ければ最新の 1 件。**確認が要るのは機体からの警告・エラーだけ**: 行の右に「確認」ボタン(警告はアンバー、エラーは赤の `.ackbtn`)。押すと「確認済み」になり行を薄くし、確認したことをログに残す。情報・正常は操作不要。見出しの数字は確認待ちの件数、右の山形でこの機体に絞った履歴シート(§1)を開く。メッセージが無ければ「メッセージはありません」。

### 3.4 右パネル AI チャット
- 対象機体セレクト、吹き出し(ユーザー / Bot / ツール実行カード: 最終受信・映像・ツール履歴)、入力欄 + 送信。
- **提案のみ**(2026-10-24): AI は読み取りツール(状態取得・機体一覧・最近のメッセージ・ログ検索)と `propose_command` だけを使う。送信ツールは無い。提案のみで、実行はオペレーター(70 §4)。
- 実装(2026-10-24、`glass_ops_ai.png`):
  - 開き方: ナビの「AI チャット」は別画面ではなく、運用マップの右パネルを開閉する(プロトタイプの `toggleAi`)。運用マップで AI が開いていれば詳細に戻し、それ以外は運用マップへ移って AI を開く(モーダル・操作卓は閉じる)。「運用マップ」ボタンは詳細に戻す。他のナビは右パネルの状態を変えない。レンズは AI が開いている間だけ AI チャット。パネルの閉じる(X)で詳細へ。機体未選択でも開け、開いている間は詳細パネルの代わりに出る(全コマンドのドックはそのまま使える)。ナビの未読ドットは出さない。
  - ヘッダー: 「AI」、対象機体セレクト(機体の選択と連動)、閉じる。その下に「プロバイダー · モデル」。対象を変えても会話は続き、各質問はその時点の対象で送る。
  - 吹き出し: ユーザーは右寄せ(時刻は左)、Bot はアバター(bot アイコン、アクセント色の円)+ 吹き出し + 時刻。待っている間は回転アイコンと「考えています…」。応答はストリーミングしない。
  - ツール実行カード(吹き出しの下、左 40 px 字下げの inset): その応答の最後の状態取得から「最終受信」(「1.8 秒前」)と「映像」(受信中 / 確認中 / 未接続 / なし。サーバーはフレームの経過時間を持たないので**状態を出し、経過時間は出さない**)。髪線の下に「ツール実行履歴」: 各ツールの成否アイコン(緑の circle-check / 赤)、「状態取得・完了」などの名前、時刻、「対象: UAV-03」。状態取得の無い応答は履歴だけ。
  - 提案カード: 「AI の提案」(sparkles アイコン)、コマンドと値、対象、AI の理由、「却下」/「実行」(破壊的なコマンドは赤)。実行は通常のコマンド経路で、要確認コマンドは確認ダイアログに「AI の提案: <理由>」を添える。結果で「実行しました」/「却下しました」/「期限切れ」(120 s)/ エラー文(再試行可)。1 回だけ使える。
  - 未設定(`[ai]` 無し・`provider = "none"`・Anthropic のキー無し): inset「AI は未設定です(config.toml の [ai])」を出し、入力欄を無効にする。ナビボタンは有効のまま。
  - 会話が上限(20 往復 / 20 万文字)に達したら「会話が長くなりました」と「新しい会話」。サーバー再起動で会話が消えていれば新しい会話として 1 回だけ送り直す。
  - 入力欄 + 52 px の送信ボタン(Enter で送信、IME 変換中は送らない)。

### 3.5 全コマンド・Guided 移動
- 全コマンド(`modal:'commands'`、右寄せ 380px シート): 検索、グループ(飛行 / 移動 / モード・ミッション / 機体・ペイロード)。ARM は ARM 済みなら無効、DISARM は逆。「カメラ・ジンバル」は操作卓(§4.2)を開く。「離陸」(2026-10-23、飛行グループの先頭、要確認): ARM 済みのときだけ有効(無効時の title「アームしてから」)。Copter / QuadPlane は高度入力(30 m から、−5 / +5)→ GUIDED に切替えて NAV_TAKEOFF でその高度へ上昇。固定翼は高度入力なしで「TKOFF_ALT まで上昇」と表示し TAKEOFF モードへ。Rover には出さない。確認ダイアログは「離陸 → 30 m」(固定翼は「離陸 → TKOFF_ALT」)。
- 確認が必要なコマンド(70 §1)は確認ダイアログを経て `confirm_token` 付きで送信。結果はフッターとメッセージ欄に出る。
- Guided 移動(`modal:'guided'`): 地図クリックで目標、高度「現在維持 / 指定(ホーム相対)」、「移動開始」。目標が未指定なら無効。地図上に目標マーカーと線。

受け入れ条件: 20 機のダミーでリスト・マーカー・パネルが 10 Hz 更新で 60 fps 近くを維持。追従中の機体が可視領域中央 ±4px。カメラ帯は能力表どおりに出し分ける(UAV-02 相当でセグメントが消える)。

## 4. 全機体映像(`view:'video'`)

- 実装(2026-10-20): ナビの「全機体映像」を有効化。グリッド ⇄ 操作卓を切替(右パネルの映像サムネイルの最大化からも操作卓へ)。運用マップは裏で保持し非表示(コントロールも隠す)。操作卓の地図は運用マップと同じレイヤーの 2D 地図で、最大化した機体を追従。機体リスト・詳細パネルはこの画面では出さない。サーマル温度・AI 追跡・SD・時刻同期の行と操作は 2026-10-23 実装済み(40 §7.1)。ROI(チップ行・状態カードの ROI 行・地図マーカーと視線・状態行の ROI 名)は 2026-10-22 実装済み。

### 4.1 グリッド(`glass_video_grid.png`)
- 全機体のタイル(自動折返し、最小 360px)。左上に種別・名前・モード・警告、右上に AUTO REC と最大化。下に高度 / 速度 / バッテリー。映像未接続タイルは暗い面に「映像未接続」。
- 選択機のタイルはアンバー枠。クリックで選択、最大化でカメラ操作卓。

### 4.2 カメラ操作卓(`glass_cockpit_rgb.png` / `_ir.png` / `_mavlink.png`)
- レイアウト: 左 2.6fr に映像、右 1fr に地図(上) + カメラ状態カード(下)。
- 映像: WebRTC(WHEP)。左上に名前・モード・テレメトリ・AUTO REC(操作不可、`pointer-events:none`)。右上に「ソース | 遅延 ms」ピルと元に戻すボタン。
- **操作バー**(映像下部中央のピル; 能力でゲート): 録画、写真、ズーム(− / 対数スライダー 1〜最大 / + / 倍率)、映像タイプ(RGB / IR / 2画面)、ジンバルモード(Lock / Follow / FPV)、センター、AI 追跡トグル、歯車。
- **ROI チップ行**(名前付きプリセットがあるときだけ): 「ROI」+ プリセットチップ(追従中は緑塗り)+「停止」。チップを押すと追従開始(Follow に固定、AI 追跡は解除)。もう一度で停止。
- **映像オーバーレイ**: 追跡枠(`.trk`: 選択中アクセント破線 → 追跡中 `--ok` 実線 → 見失い `--caution`)、枠の上に状態タグ。IR 表示のとき最高(赤)・最低(水色)温度マーカー + 温度値(温度表示が ON のとき)。
- **クリック操作**: 映像クリック = その位置を中心に追跡ボックス(既定 100 px、設定で変更)で AI 追跡開始(RGB 表示のときだけ)。Ctrl + クリック = カメラの検出枠から対象を選択(検出枠は水色で表示)。Alt + クリック(IR) = その点の温度を 15 秒表示。
- 2 画面(side by side): 左 RGB、右 IR。クリック追跡は不可。
- 実装の決定(2026-10-23):
  - 映像は全面表示なので `object-fit: cover`。重ね描きとクリックは `<video>` の `videoWidth` / `videoHeight`(無ければ `camera_state.stream`、それも無ければ 16:9)と要素の大きさから求めた cover の矩形で正規化 0..1 と相互変換する(切り取られた側ははみ出す)。クリックはその時点で測り直す。
  - Ctrl + クリックは macOS の ⌘ + クリックでも同じ。macOS の Ctrl + クリックはブラウザでは右クリック(`contextmenu`)として届くので、Ctrl 付きの `contextmenu` もクリックとして扱う。映像上の右クリックメニューは出さない。Alt + クリックは IR のときだけ(他は「温度測定は IR 表示でのみ使えます」)。IR で Alt なしのクリック、RGB 以外の AI追跡ボタンは「AI 追跡は RGB 表示でのみ使えます」(ボタンは無効表示 + title)。解像度未取得(エンコード変更直後)は「映像の解像度がまだ不明です」。拒否と AI の失敗 ACK(`ai_ack` の `ok` 以外)は操作ログに出す。
  - クリックした位置にアクセント破線の `.trk` を最初の 0x50 が届くまで(最大 1.5 s)出す(ボックスの大きさはサーバーが選ぶ画素枠と同じ丸め)。追跡中は `.trk.tracking`、再捕捉中 / 見失いは `.trk.lost`。検出枠(`.cand`、水色 1px)は RGB のときだけ。
  - 温度マーカーは IR かつプロファイルの `thermal_overlay` が ON のときだけ。Alt + クリックの点は色なしの `.tmark`(サーバー側で 15 s)。2 画面では温度もクリックも無し。
  - AI追跡ボタン(`btn btn-sm`、追跡中は `on`)はセンターの後。追跡中は解除、それ以外は画面中央に 200 px の枠で開始(ジョイスティックの `ai_tracking_toggle` と同じ)。
- **地図(ミニ)**: 運用マップと同じレイヤー。最大化した機体を中心に `jumpTo`。
- **カメラ状態カード**: ジンバルダイアル(ヨー ±90° を横、ピッチを縦に投影した点、上に機首マーク)。行: ジンバル(モード、ヨー / ピッチ)、ROI(名前、方位、距離)、サーマル(ゲイン、最高 / 最低)、SD カード(空き / 総量 / %、空き 10% 未満は `--danger`)、カメラ時刻(GPS 同期との差)、映像(エンコード、ソース、遅延)。能力に無い行は出さない。
- **ジョイスティック**: 操作卓表示中に限らず、ジンバル操作デバイスが有効なら常に「選択中の機体」のカメラに送る(40 §6)。

受け入れ条件: MT11 で全操作が出る。MAVLink カメラでは録画 / 写真 / ズーム / ジンバル行だけ(2026-10-23 の読み方: サーマル / SD / 時刻 / ROI 制御 / AI を出さないという意味。状態カードの「映像」行はカメラの機能ではなく映像リンクなので残す。ズームは % 表示でスライダーは線形)。クリック追跡で枠が出て `camera_state.track` と一致する。ROI チップで `roi_status.active_target` が切り替わる。遅延表示が受信側の実測。

## 5. カメラ設定シート(`modal:'camera'`、`glass_camera_settings_*.png`)

- 右寄せ `g-strong` シート 440px(運用マップ・操作卓どちらからも開ける)。ヘッダー: 機体名 + 「カメラ設定」。タブ 4 つ。下部に「キャンセル」「保存」。保存は全タブの下書きをまとめて `PUT …/camera/profile`、`PUT …/roi/targets`、`PUT …/roi/control`、`PUT /api/settings/input/gimbal` に送り、結果をフッターに出す。
- **接続**: カメラ種別(なし / MAVLink カメラ / SIYI MT11)。MT11: IP、制御ポート(37260)、RTSP(自動生成、表示のみ)、映像ソース(AUTO / MT11 / 補助)、状態(接続、FW camera / gimbal / zoom、SD、カメラ時刻 + 今すぐ同期)。MAVLink: コンポーネント ID(1–255、既定 100)、RTSP URL、状態(接続、FW `cam x.y.z`。SD / 時刻は無し)。RTSP URL のホストが IPv4 リテラルなら `host` にその値を入れる(60 §3.9 の「RTSP のホストはカメラの IP」を満たすため。2026-10-23)。種別を MAVLink に切り替えると `{host}` の雛形を実際の URL に展開し、MT11 に戻すと雛形に戻す。なし: 注記。
- **操作**: ジンバル操作デバイス(アプリ設定と共有)。軸割当表(軸 / 機能 / 不感帯 / 反転)。ボタン割当表(ボタン / 機能)。最大パン速度・最大チルト速度(1–100)。「ジンバルをセンター」。機能一覧は 40 §6。
- **ROI**: プリセット 10 行(# / 名前 / Lat / Lon / MSL)。「地図で指定」= 次の空き行を対象にシートを閉じ、地図クリックで座標と地表標高を入れて戻る(上部中央にヒント)。「CSV」= `名前,lat,lon,alt` を読み込み(先頭 10 行、UTF-8 / Shift_JIS、不正行があれば中止)。制御: rate / angle、Kp / Ki / Kd、不感帯、平滑化 τ、最大速度、ヨー補正。範囲は 60 §3。
  - 実装の決定(2026-10-22):
    - CSV: 先頭の空でない行で lat と lon がどちらも数値でなければ見出し行。11 行目以降は検証せず「スキップ」として数える。読込は 10 枠すべてを置き換え、行の無い枠は空になる(Python `toRoiTargets`)。BOM 付き / 無しの UTF-8、それ以外は Shift_JIS。MP の `poi.txt`(高度なし)の読込は範囲外。
    - 地図で指定: 地表標高は Terrarium DEM(`settings.terrain_tiles`)から、タイル待ち最大 3 s。取れなければ選択機の `home.alt`(MSL)、それも無ければ 0 とし、どちらの場合も注意表示を出す。名前が空なら `ROI n`。シートの編集中の内容は地図指定の往復で失われない(キャンセルでも ROI タブへ戻る)。
    - カメラが ROI 非対応(`caps.roi = none`)なら ROI タブは無効表示(title「このカメラは ROI に対応していません」)。
    - `caps.roi = native`(MAVLink カメラ、2026-10-23)では制御欄(rate / angle / PID)を出さず「ArduPilot がジンバルを目標に向けます」を出す。プリセット下の注記は MT11 専用の「追従中は Follow モードに固定されます」を省く。
- **映像**: エンコード(5 プリセット)、サーマルパレット(11 種)、ゲイン(High / Low + 測定レンジ表示)、温度表示 On/Off、追跡ボックス px、ARM で自動録画 On/Off。MT11 以外はエンコード〜追跡ボックスを出さない。
  - 保存(2026-10-23): 映像タブの項目(`encoding_preset` / `thermal_palette` / `thermal_overlay` / `ai_box_px` / `auto_record`)はドライバを作り直さずに保存する(50 §2.3)。続けて、変わった値だけ `Encoding` / `ThermalPalette` / `ThermalGain` コマンドを送る。接続の項目も変わった保存ではコマンドを送らない(作り直しでカメラが一時オフラインになるため)。パレットは読み返せないので保存値を表示し、ゲインは保存せずカメラの現在値(`thermal.gain`)から下書きを始める。
- 入口: カメラ帯・操作卓の歯車、全コマンドの「カメラ・ジンバル」は操作卓、アプリ設定の「カメラ設定で割当を編集」(操作タブで開く)。

受け入れ条件: 種別変更 → 保存で UI の操作が即座に出し分け変わる。無効値(範囲外)は保存前に赤で示し送信しない。地図で指定した座標がプリセットに入り、ROI マーカーが増える。

### 6.2 予測飛行経路(2026-10-20、Plane / QuadPlane / Copter)
- 対象機体が Plane / Copter のとき、計画の上に「実際に飛ぶと予想される経路」を重ねる: 2D は細い破線(半透明)、3D は細い半透明線(上昇率で着色)。計画の直線は主線のまま。風は考慮しない推定。
- 元データは機体のパラメータ(`GET /api/vehicles/{sysid}/params/pick?names=…`: キャッシュ値 + 無いものは PARAM_REQUEST_READ で取りに行き最大約 1 秒待つ)。AIRSPEED_CRUISE、WP_LOITER_RAD、ROLL_LIMIT_DEG、TECS_CLMB_MAX / SINK_MAX、ALT_SLOPE_MIN、FLIGHT_OPTIONS、NAVL1_PERIOD / DAMPING、Q_ENABLE、Q_OPTIONS、Q_WP_SPD*。最後に読めた値はブラウザに機体ごとに保存し、未接続でも使う(無ければ ArduPilot 既定値)。
- 挙動(ArduPilot master 2026-10-20 のソースと SITL QuadPlane 飛行で確認): 速度は EAS→TAS(ISA)、旋回半径 v²/(g·tan ROLL_LIMIT)、ロイター半径は R·EAS2TAS²、ロイターへは中心に向かい手前側から合流、高度変化は中心までの勾配(ALT_SLOPE_MIN 以上)+ TECS の上昇・降下率で円上は螺旋、LOITER_TO_ALT は 5 m 以内まで周回して次 WP への接線で離脱、xtrack 0 は中心→次 WP の線へ L1 で収束、LOITER_TIME の半径は常に WP_LOITER_RAD(param3 は向きのみ)、QuadPlane の NAV_TAKEOFF / NAV_LAND は Q_OPTIONS が許さない限り垂直、DO_VTOL_TRANSITION(3) 後のロイターはホバー。
- 追加コマンド: LOITER_TO_ALT(31)、VTOL_TAKEOFF(84)、VTOL_LAND(85)、DO_VTOL_TRANSITION(3000)。VTOL 離着陸で始まり終わるミッションを検証で受け付ける。
- ロイターへの進入(2026-10-20 改訂): 直前の WP は turn_distance(min(WP_RADIUS·EAS2TAS², L1 距離)、90° 未満の旋回は比例縮小)手前で到達扱い(機体ログ「Reached waypoint #2 dist 88m」と一致)、そこからの合流は AP_L1_Control::update_loiter の時間刻みシミュレーション(ロール立ち上がり約 1 秒、SITL の膨らみ 438 m に合わせた)。VTOL 離陸直後の遷移方向は機首方位次第なので予測しない。
- Copter(2026-10-20、ArduCopter master のソースと SITL 飛行で確認): パラメータは WP_SPD / WP_RADIUS_M / WP_SPD_UP / WP_SPD_DN / WP_ACC / WP_JERK / WP_ACC_CNR / RTL_ALT_M / RTL_ALT_FINAL_M / RTL_CLIMB_MIN_M / RTL_CONE_SLOPE(4.7 で改名。旧名 WPNAV_* / RTL_ALT 等の cm 値も読む)。WP は停止せずに通過するのは次が WAYPOINT / SPLINE / ARC / LOITER_UNLIM / LOITER_TIME / LAND 等で待機 0 のとき、角は SCurve の重ね合わせ(前区間の減速中に次区間を始める: 中間点が WP_RADIUS_M 以内・中間点の速度が区間速度以下・横加速度が角加速度以下)。速度は加速度・ジャークの S 字(短い区間は最高速度を下げる)。SPLINE はエルミート曲線(接線は前後の点から、SPLINE_FACTOR 4 で制限)、ARC は円弧、LOITER_TURNS は最寄りの縁へ移って周回(負の半径は反時計回り)、離陸は垂直、RTL は円錐勾配で決めた高度へ上昇→帰還→降下。SITL 飛行(直線・角・スプライン・LOITER_TURNS・RTL、981 点)との水平距離は p50 0.1 m / p90 0.7 m / 最大 1.0 m(角の切り込みは予測が約 0.7 m 大きい)。
- WP の角(2026-10-21 改訂、SITL 飛行との比較で確認): 固定翼の WAYPOINT は直線 + 円弧(fillet)ではなく ArduPlane の L1 どおり。区間は WP の到達距離(param2 > 0 ならその値 m(AP_Mission の 1 バイト、最大 255)、0 なら turn_distance)手前で終わり、そこから次区間の線(始点は WP 自身、`set_next_WP`)へ AP_L1_Control::update_waypoint の横加速度(K_L1·v²/L1·sin Nu、ROLL_LIMIT とロール遅れ)を時間刻みで追う。鋭い角では WP を過ぎてから戻る膨らみまで描く。ARC / SPLINE WP とロイターは従来どおり。
- ミッション後の RTL(2026-10-21): 最後の項目の後 ArduPlane は RTL に入る(commands_logic.cpp exit_mission)ので、ミッションが LAND / VTOL_LAND / RTL で終わらない限り、最後の高度のままホームへ戻り WP_LOITER_RAD で 1 周する区間を予測に足す。RTL_ALTITUDE、RTL_RADIUS、ラリー点、Q_RTL_MODE はモデル化しない(帰還先は常にホーム、高度は最後の高度)。

### 6.3 作成画面の操作追加(2026-10-20)
- 開いたとき・対象機体を切り替えたときは、その機体の位置へ地図を移す(以後の機体の移動では動かさない)。
- 方位表示の下に「場所を検索」(地名・住所は OpenStreetMap Nominatim をブラウザから検索、「緯度, 経度」はそのまま移動)と「機体の位置へ」(複数機なら一覧から選ぶ)。
- 空のミッションの最初のクリックは機体に合った離陸から始める: QuadPlane(Q_ENABLE)は VTOL_TAKEOFF、Copter / Plane は NAV_TAKEOFF、Rover は離陸なし。

- 機体に書き込む: 接続中(link が lost 以外)が 1 機ならそのまま、複数なら機体選択シート(すべて選択 / すべて解除 / 個別、対象機体は最初から選択)を挟み、選んだ機体へ順に検証→書込。
- Fence / Rally タブ(2026-10-20): 左はゾーン / ポイントの一覧、右パネルはタブ専用(フェンス: 包含・除外の数、FENCE_ALT_MAX、機体へ書込 / 読込、ファイル保存 / 読込。ラリー: 点数、書込 / 読込、ファイル)。ファイルは Mission Planner 互換の QGC WPL 110(MAV_CMD_NAV_FENCE_* / NAV_RALLY_POINT、ポリゴンの頂点数は param1)で保存し、読込はそれと QGroundControl の .plan(geoFence / rallyPoints)。読込は今のリストを置き換える 1 回の編集(取り消し可)。
- ファイルは Mission Planner と相互運用(MissionPlanner master のソースで確認、2026-10-20): ミッション = `.waypoints`(QGC WPL 110、行 0 がホーム)。フェンス / ラリー = MP の FlightPlanner と同じ書式(行 0 にホーム行、項目は seq 1 から frame 3、param は小数 8 桁、CRLF。MP はフェンス / ラリーの読込で行 0 を捨てるため)。読込は MP の旧 `.fen`(戻り点 + 閉じたポリゴン)/ `.ral`(`RALLY lat lon alt …`)と QGC `.plan` も可。POI = MP の `poi.txt`(`lat<TAB>lon<TAB>名前` CRLF、`features/mission/poiFile.ts`。POI 機能とカメラ ROI で共用予定)。
- ミッション / フェンス / ラリーのファイル読込が成功したら、読み込んだものに地図を合わせる(左右パネルを避けた余白で。1 点ならその点へ寄る)。

### 6.4 複数のフライトプラン(2026-10-21、2026-10-31 改訂)
作成画面では名前を付けたフライトプランを複数同時に開き、重ねて見比べ、機体に割り当てて書き込める(設計 `docs/superpowers/specs/2026-10-20-multi-mission-briefing-design.md`、§9 の追加要望を含む)。フライトプラン = 保存済みミッション(`/api/missions` の 1 件、内部では `id` で管理)。2026-10-31 に「ブリーフィング」(開いているプランの組を名前付きでサーバーに保存する入れ物)を廃止した。分かりにくいという判断で、組はブラウザに残すだけにした。
- 左パネル上部: 「開いているプラン」の一覧(行ごとに色チップ・プラン名・未保存の印・割当機体のチップ・表示 / 非表示・▲▼・一覧から外す)。割当機体のチップは保存済みプランを割り当てた機体の名前を並べるだけ(読むだけ、無ければ「未割当」)で、押すと割当モード(§6.6)を開く。行を押すと編集対象が切り替わる(取り消し履歴・選択・未保存はプランごとに保持)。行のダブルクリックでそのプラン全体(経路・フェンス・ラリー、ホームは除く)を左右パネルを避けた範囲に収める。プランが 1 つなら色チップと割当欄が増えるだけの見た目。
- 右パネル上部: 「新しいプラン」「プランを開く」「保存」と「プラン名」。新しいプランの名前は「新しいプラン」。保存は編集中のプランだけを `/api/missions` に作成 / 更新する。
- 追加: 「ファイルから読込」は複数ファイルを一度に選べ、1 ファイル 1 行。プランを開く / 機体から読込 / 新しいプランも、手を付けていない編集中の行なら置き換え、そうでなければ行を足す。同じ保存済みプランは 2 行にしない(既存の行を選ぶ)。
- 保存済みプラン(「プランを開く」のシート): 名前・項目数・更新日時。行ごとのゴミ箱ボタンでシート内の確認(「〜を削除しますか。元に戻せません。」)を挟んで `DELETE /api/missions/{id}`。開いている行はそのまま残り、未保存のプランになる(保存し直すと新しいプラン)。運用画面の「ミッション書込」シートには削除ボタンを出さない。
- 開いているプランの組(行・色・表示状態・編集中の行)はブラウザの `rgcs.plans.v1` にだけ保存し、再読込で戻す(旧 `rgcs.briefing.v1` は一度だけ読み、消す)。プランごとの機体は保存時にプラン(`missions.sysid`)にも残る。
- 色: 彩度の高い 8 色(色相を離した固定パレット)。新しい行は未使用の色のうち既存の行の色と選択色(アンバー)から最も離れたもの。行・比較表・地図(編集中の経路も含む)で同じ色。1 プランだけのときは従来の高度の色分け。
- 地図: 全プランの計画線・フェンス・ラリーを行の色で重ねる(編集中以外は半透明・細線で操作不可)。予測経路は編集中のプランだけに描き、他のプランは計画線のみ。3D も同様(他のプランのフェンスは地表に貼る)。非表示の行は地図から消えるが、比較表と一括書込には残る。交差・接近の札はユーザーの判断で出さない(色分けと 3D で確認)。
- 右パネル(Mission / Fence / Rally)は右上のボタンで細いレールにたためる。状態はブラウザに記憶し、地図の余白も合わせる。
- 比較表(Mission タブ): プラン・機体(割り当てた機体の名前。複数機なら並べる、無ければ —)・距離(主)・時間(目安)・バッテリー(目安 = 所要時間 ÷ 機体台帳の「飛行可能時間(分)」、70% 超でアンバー、未割当 / 未設定は —)。注記「残量 30% で帰還する前提」。機体台帳の `endurance_minutes` はメンテナンス › アプリ設定で編集。
- 割当(2026-10-31 改訂): 行ごとの機体プルダウンと比較表の「割当どおり書き込む」は廃止し、割当と一括書込は割当モード(§6.6)に一本化した。右パネルの「対象機体」は編集中の行の 1 機書込の書込先で、「機体に書き込む」は保存済みで未変更のプランなら `POST …/mission/upload {mission_id}` で書いて書込記録を残し、未保存の内容は内容そのものを書く(記録は消え、割当モードでは書込待ち、未接続なら不明)。
- 確認(2026-10-21、SITL Copter・上高地の 3 エリア `tests/fixtures/briefing/`): 3 ファイル同時読込、割当、行切替後の編集保持、非表示、ダブルクリックで寄せる、パネルたたみ、3D。

### 6.5 サーベイ(2026-10-21)
固定翼(QuadPlane を固定翼モード)で下向きカメラの距離トリガ撮影を計画する項目(設計 `docs/superpowers/specs/2026-10-21-survey-grid-design.md`、実装 `apps/rgcs-server/ui/src/features/survey/`、カメラ一覧 API は spec 50 §2.2.3)。機体に書くのは普通のミッション項目だけで、サーベイは `Mission.items` の範囲に付けた付箋(`Mission.surveys: [{ id, first, count, spec }]`)。
- 追加: 「コマンドを挿入」のパレットに「サーベイ」と「KML から読み込む」。サーベイは地図クリックで頂点を足し、Enter または最初の頂点で完了、Esc で取り消し(描画中は WP の追加・ドラッグ・中点挿入・矩形選択を止める)。KML は `Polygon` の外周だけを読み、複数あれば選ばせ、穴は無視したと知らせる。壊れた座標は全体を拒否(`bad_coordinates`)、5,000,000 文字 / 1 リング 10,000 頂点 / 50 ポリゴン超は `too_large`。既定値で生成して選択中の項目の後ろに 1 手で挿入する(選択がサーベイ内ならそのサーベイの後ろ)。名前は描画なら「1」「2」…、KML は Placemark 名(無ければ表示言語で「エリア N」)。KML の理由表示は × で閉じられる。
- 既定値: カメラは組込み「Sony α7R IV 35mm」(一覧の読込前でも同じ値)、高度 100 m、前後 80 % / 左右 70 %、方角は多角形の最長辺に平行、開始はホーム寄り、速度 18 m/s(コプター 8。接続した固定翼は AIRSPEED_CRUISE)、風 0、ライン飛ばしは固定翼なら推奨本数(隣のラインが旋回直径 2R 以上離れる最小、上限 10)・コプター 0、旋回 WP 分割、バンク 30°(接続機の ROLL_LIMIT_DEG が小さければそれ)、WP_RADIUS は接続機の値(無ければ 90 m)を spec に写す。機体パラメータは読むだけで書かない。機体の値が後で変わっても作り直さない。
- 一覧: サーベイは 1 行(`サーベイ {名前} · {n} WP · {枚数} 枚`)にまとめ、▸ で展開すると生成項目を機体に書く番号どおり薄く読み取り専用で並べる(撮影開始・停止、旋回の分割 WP を含む。行を選ぶと地図・3D で示す)。行を押すとサーベイを選び右パネルがサーベイ用になる。▲▼・ドラッグ並べ替え・パレット / 右クリックの挿入・⌘V 貼り付けはサーベイを割らず、その前後に置く。
- 右パネル(上から): カメラ(一覧から選択、センサー幅×高さ・画素数・焦点距離・シャッター・最短撮影間隔、長辺の向き 横 / 縦、名前を付けて保存・更新・削除。組込みは更新・削除不可)、解像度(cm/px)⇔高度(m)、前後・左右オーバーラップ、ラインの方角、開始位置(北西 / 北東 / 南西 / 南東 / ホーム寄り)、速度、想定風速、ライン飛ばし、旋回(WP 分割 / ArcWaypoint)とバンク角(接続機の ROLL_LIMIT_DEG を横に表示)、助走・行き過ぎ・範囲外の余白(空欄 = 自動)。数値: 写真枚数、撮影距離 / 間隔、ブレ(cm / px)、フットプリント、面積、ライン数、旋回半径、総距離、推定時間、範囲内の地表の最低–最高標高と、解像度・前後・左右の設定値 / 最悪値(地形データが無ければ出さない旨)。最下部に「ウェイポイントに展開」(付箋を外して普通の WP にする。取り消しで戻る)。
- 編集: 値の変更は即座に作り直して地図・数値・一覧に出す。入力中・ドラッグ中はプレビューだけで、確定(Enter / フォーカスを外す / ドラッグを離す)で 1 手の取り消し履歴。作り直すと選択は新しい先頭項目へ移る。範囲外の値、線を作れない多角形、大きすぎるサーベイ(ライン 1,000 本 / 項目 5,000 超、多角形 10,000 頂点超、`too_large`)は反映せず、そのサーベイのパネルにだけ理由を出す。作成時に大きすぎれば何も挿入せず一覧の上に理由を出す(固まらずに断る)。取り消し / やり直しは条件の変更も 1 手。カメラ一覧・保存の失敗は辞書の文言で示し、サーバーの文言は小さな補足だけ。パネル内(と、ボタン・ラジオなどの操作部品の上)のキーは編集ショートカット(Delete・⌘Z・矢印など)にしない。
- 生成: ライン間隔は左右オーバーラップ、撮影距離は前後オーバーラップから。多角形を余白(既定 = フットプリントの半分、軸ごと)だけ外へ広げて切り、凹形で分かれた区間は別ライン。ライン飛ばし n は n+1 本先へ移り、飛ばしたラインは後で埋める。開始隅は「最初 / 最後のライン × どちらの端から入るか」の 4 候補から地理(北西なら北 + 西が最大)で選び、ホーム寄りは入口がホームに最も近いもの。1 本 = 助走開始 WP → 撮影開始 WP + `DO_SET_CAM_TRIGG_DIST [距離, 0, 1, 0]` → 撮影終了 WP + `DO_SET_CAM_TRIGG_DIST [0, 0, 0, 0]` → 行き過ぎ終点 WP → 旋回。先頭に `DO_CHANGE_SPEED`(Plane `[0, 速度, -1, 0]` 対気速度 / Copter `[1, 速度, -1, 0]` 対地速度)。サーベイ後の速度は戻さない。撮影の位相はライン間で揃えない。全点 REL の一定高度。
- 旋回: 半径 R = v²/(g·tan バンク)、v = 速度 + 想定風速。ライン間の距離 d ≥ 2R は 1/4 円弧 + 直線 + 1/4 円弧、d < 2R は外へ膨らむ Ω 形(3 円弧、長い方のライン端まで両ラインを延ばしてから回る)。WP 分割は 1 区間 30°(`ARC_SPLIT_DEG`)以下の等角度、1° 未満の弧と 0.5 m 未満の重複 WP は出さない。ArcWaypoint は弧の終点に `NAV_ARC_WAYPOINT`(param1 = 整数の角度、時計回り +)。助走の自動値は ceil5(max(R, 8 × (速度 + 想定風速)))(旋回後 8 秒はラインに乗る)、行き過ぎは ceil5(R/2)(5 m 単位の切り上げ)。コプターは旋回なし(助走・行き過ぎ 0、旋回の項目は隠す)。
- 注意(色で示すだけで書込は止めない): ブレ > 1 px(最悪の解像度で)、撮影間隔 < カメラの最短撮影間隔、ライン飛ばしが旋回直径に足りない(推奨本数付き)、バンク角 > ROLL_LIMIT_DEG、最悪オーバーラップが設定 −10 ポイント未満、ArcWaypoint(Plane / QuadPlane は 36 を実行しない可能性)、予測軌道(ミッション部分だけ。末尾の RTL 区間は判定に含めない)が撮影開始 WP から 5 m(`ENTRY_TOL_M`)以上離れる、WP_RADIUS(ArduPlane は WP を min(WP_RADIUS, L1) × 旋回角 / 90 手前で通過扱いにする(commands_logic.cpp)。一直線上の助走・撮影開始・終了・行き過ぎ WP は到達線で受け付けられるので注意しない。WP 分割で min(WP_RADIUS, L1) × 30/90 > R·sin 15° なら分割 WP が早めに離され旋回が切り上げられる)、L1(R < L1 距離 = NAVL1_PERIOD × NAVL1_DAMPING × (速度 + 風) / π。値は接続機、無ければ ArduPlane の既定。旋回は描いたより大回りになる。ライン飛ばしを増やすか NAVL1_PERIOD を下げる)、地表の接近(最低対地高度 = 高度 + ホームの地表 − 範囲内の最高地表 が 30 m 未満。上回れば「飛行高度より N m 高い地表」)、VTOL アシスト・失速(速度 ≤ Q_ASSIST_SPEED(正のとき)または < AIRSPEED_MIN + 2 m/s。値が読めなければ出さない)、CAM_MAX_ROLL(CAM1_MAX_ROLL)が 0(バンク中も撮影する。設定すれば ArduPilot はバンク中の撮影を見送る。値が読めなければ出さない)、サーベイの項目 > 700、ホーム未設定(ホーム寄りは北西になる)。「助走」「WP_RADIUS」「L1」「VTOL アシスト」「ライン飛ばし」「予測軌道」は固定翼だけ。有限でない数値は「—」と表示する。
- 地図: 2D は多角形(頂点ハンドルでドラッグ編集)、撮影区間(太線)、助走・旋回(細線)、撮影点(ズームで表示)、写真フットプリント(「撮影範囲を表示」で切替、ブラウザに記憶)、方角の回転ハンドル(ライン方向に半幅の 1.25 倍、0–360°)。ハンドルはミッションタブで描画中以外、全サーベイに出す。ドラッグ中は 1 フレーム 1 回のプレビューで、中点 + と予測軌道は確定した下書きのまま止め、離したときに 1 手で確定。生成 WP の番号バッジはそのサーベイを選んでいるときだけ出し、ドラッグはできない。サーベイ内の区間には中点 + を出さない。3D は多角形の外周を地表に貼り、生成 WP は既存の空中経路で示す(足のハンドルも出さない)。3D の浮かせ表示は、テレメトリ更新では機体だけを、カメラが動いたフレームでだけ計画の全マーカーを動かし、地表は DEM サンプラーの値で投影する(長い計画 + 飛行中の機体で固まらない)。予測軌道(§6.2)はサーベイの spec の速度・バンク・WP_RADIUS で重ね、ミッション後の RTL 区間(ホームへ戻る線)も含む。
- 付箋の維持: サーベイは項目の uid で追う(前に挿入・削除しても保たれる)。サーベイの項目は通常の編集経路では読み取り専用: 地図のドラッグ・3D の高度 / 位置ドラッグ・矢印キーの微移動・高度一括・円弧化は無視する。Delete / Backspace / 右クリック削除でサーベイの項目を含めて消すと、そのサーベイ全体(項目と付箋)を 1 手で消す。それ以外(右パネルの項目編集など)で範囲内の項目を変えるとサーベイを外して普通の WP にし、一覧の上に「サーベイ「{名前}」の項目を編集したため通常の WP にしました(⌘Z で戻せます)」を出す(同じ名前は 1 回、「元に戻す」ボタンと × 付き。取り消しで戻り、知らせも消える)。一覧の行の数値は小数 2 桁まで。保存・`.rgcsmission`(version 1 のまま、`surveys` は任意欄)に条件と多角形が入り、開き直しや読込では作り直さず保存された items を使う。書込・検証・統計・プランの比較・`.waypoints` は展開後の WP 列を使う。

### 6.6 プランの割当(割当モード、2026-10-31)
保存済みプランをどの機体に書き込むかを、カードを動かして決め、まとめて書き込む(設計 `docs/superpowers/specs/2026-10-31-plan-assignment-board-design.md`、実装 `apps/rgcs-server/ui/src/features/assign/`)。割当はサーバーの状態(`plan_assignments`、spec 50 §2.2.2 / spec 60 §3.12)で、ほかの画面にも WS の `assignments` フレームで即座に反映する。1 プランを複数機に割り当てられ、1 機に入るのは 1 プランだけ。
- モード: 地図上部の「編集 | 割当」で切り替える(状態は画面の中だけで URL には出さない。編集の取り込み・書込中などエディタが忙しい間は隠す)。割当では左右のパネルがボードに替わり、地図は残る。編集に戻ると直前の編集状態(行・選択・取り消し履歴)がそのまま戻る。開くたびにプランの一覧を読み直し、全プランと位置の分かる全機体が入る範囲に地図を合わせる(左右パネルを避けた余白)。
- 左: プランのカード。ライブラリの保存済みプラン全部(開いていないものも)を名前で絞り込める。カードは色チップ・名前・距離・離陸あり / 地上走行・タグ(「N 機に割当」/「未割当」)。色は開いている行の色、それ以外はパレットから id 順(開いている行の色は飛ばす)。開いている行に未保存の変更があるプランは「未保存の変更あり」(鍵)でドラッグもタップ選択もできず、押すと理由を出す(書くのは保存済みの内容だけ)。
- 右: 機体のカード。接続中 → 未接続、その中は名前順。機体名・種別・モードで絞り込める(左とは別)。最大 2 列、あふれたらパネルの中だけ縦スクロールし、フッターの書込ボタンは固定。カードは種別アイコン・名前・接続・モード(アーム中は赤)・電池・GPS 未取得、割当プランのチップ(× で外す)か「ここへドラッグ」/「タップで割り当てる」/「置けません」、状態バッジ、「飛行中」(アーム中)、「電池 目安 N%」(所要時間 ÷ 機体台帳の飛行可能時間。70% 超でアンバー、100% 超で赤)、書き込む対象なら「書き込む」ボタン。
- 置けるかの判定は `Mission::validate_for(kind)` の 1 規則と同じ: Rover は離陸のあるプランを走れない、空の機体は TAKEOFF のないプランを飛べない。選択中・ドラッグ中は置けないカードを淡くして理由を出す。サーバーの致命的な検証は書込時にも効く。
- 操作(マウス・タッチ共通の Pointer Events):
  - ドラッグ: マウスは 4 px 動いたら、タッチは 250 ms の長押しで始まる(その前に 10 px 動けばスクロール扱い。開始時に短く振動)。カードの縮小版が指について動き、置けるカードは枠を強調、置けないカードは理由を出す。右の一覧は端 40 px で自動スクロールし、ドラッグ中はページをスクロールしない。機体カードへ落とすと割当、別のプランがあれば置き換え。機体カードのチップを別の機体へドラッグすると移動(元の機体は外れ、移動先は置き換わる)。Esc で取り消し。
  - タップ(または Enter): プランカードを選ぶと浮いた表示になり、続けて機体カードをタップした機体へ何機でも割り当てる。プランカードの再タップ・何もない所・Esc で解除。
  - ダブルクリック(ダブルタップ、320 ms): プランカードはそのプラン全体に寄せる(§6.4 の行のダブルクリックと同じ)。機体カードはその機体(割当があれば開始点も)に寄せ、位置が分からなければカードに「位置が分かりません」を短く出す。1 回目で入った選択は 2 回目で外さず、機体カードの 1 回目で割り当てた場合は 2 回目を寄せとして扱い割当は残す。
  - 割当の変更は楽観的に即座に表示し `PUT /api/assignments/{sysid}` で保存する。失敗すると元に戻し、フッターに理由を出す。
- 元に戻す: 割当・置き換え・移動・外すのたびに地図の下中央に 4.5 秒、「{プラン} を {機体} に割り当てました」/「{機体}: {旧} を {新} に置き換えました」/「{プラン} を {元} から {先} に移しました」/「{機体} の割当を外しました」と「元に戻す」を出す。元に戻すは関係した機体(移動なら両方)の前のプランを同じ API で戻す。次の操作はお知らせを置き換える。
- 状態バッジ: 一致(最後に書き込んだプランの id と版 `updated_at` が割当と同じ、緑)/ 書込待ち(割当と書込記録が違う、アンバー)/ 更新あり(同じプランを書いた後に保存し直された、アンバー)/ 不明 (未接続)(書込記録が無く未接続。未保存の内容を書くと記録は消え、接続中なら書込待ちに戻る)。割当なしはバッジなし。
- 地図: 割り当てたプランは行の色、割当のないプランは薄く描く。機体のマーカーから割当プランの開始点(最初の位置付き項目)へプランの色で破線(機体ごとに 1 本)。カードにカーソルを合わせる(タッチは選択中のプラン)と関係する線と経路を強調し、残りを薄くする。
- 書き込み: フッターの「変更のある N 機に書き込む」(対象は書込待ち・更新ありで接続中、種類の合う機体。無ければ「書き込む変更はありません」)とカードごとの「書き込む」が確認シート(§6.4 のシートを流用: プラン → 機体の一覧、機体に残る前のフェンス / ラリーを消す / 残す)を開く。アーム中の機体の行は赤く、チェック「飛行中の {機体} のミッションを置き換える ({モード})」を付けない限り対象外。AUTO 中はミッションの差し替えを受け付けて今の WP 番号から続ける旨を注記する。各機体へフェンス → ラリー → ミッションの順(ミッションは保存済みプランとして `POST …/mission/upload {mission_id}`)で検証 → 書込 → 照合し、1 機の失敗で他を止めない。ミッションが照合まで成功するとサーバーが書込記録を付け、カードは「一致」になる(フェンス・ラリーの失敗では「書込待ち」のまま)。書くのは保存済みの内容だけ。
- 確認: 単体テスト(`features/assign/*.test.ts(x)`)、e2e `e2e/assign.spec.ts`(SITL なしでプラン一覧・空の機体一覧・編集への戻り。`--with-sitl` でタップ割当・再読込後の保持と「書込待ち」・× で外す。e2e は機体に書き込まない)。

## 7. メンテナンス(`view:'maint'`)

- 上部: 接続機体セレクト、種別、モード、ARM 状態。タブ 6 つ(レンズ): パラメータ / 点検・校正 / 日常点検 / 飛行日誌 / 変更履歴 / アプリ設定(2026-10-17 追補 §5.7。「ログ・AI 解析」は飛行日誌内の「ログ」に縮退)。
- **パラメータ**(P4 実装): ツールバー(名前・説明の部分一致検索、取得状況 `received / total` とバー、「更新」= `PARAM_REQUEST_LIST` + 欠番の `PARAM_REQUEST_READ`)、全件テーブル(名前 / 表示名、値(列挙はセレクト、他は数値入力。範囲外は拒否)、単位、説明、範囲。300 行で打ち切り、検索で絞る)、右に**変更セット**(旧 → 新、再起動要の印、「書き込む」→ 確認(`param_write` の confirm_token)→ 1 件ずつ `PARAM_SET` + エコー検証 → 結果 ✓ / 未検証(応答なし / 不一致 / アーム中で中止)。アーム中は書込不可)。メタデータは ArduPilot の `param_parse` 出力を平坦化した `public/params/arducopter.json`(`scripts/sync-params-meta.py`)。セクション別ビューと模式図は追補 §5.4 により後送り。

- **3D 地図**(P9、2026-10-19): 運用・ミッション両画面の 2D / 3D(`seg onmap float map-r top1`、マップタイプは `top2`)。選択はブラウザごと(`rgcs.mapMode`、両画面共通)。3D は Terrarium 標高タイルの地形(`exaggeration 1`)、ピッチ 60°・方位 −25° へ 900 ms で移る。標高タイルが設定されていないと 3D は押せない(理由をツールチップに出す)。
  - 運用: 飛行中(相対高度 1 m 以上)の機体に地面からの細いポストと地面の円(選択機 `--caution`)。機体マーカーは「ホーム地点の地面標高 + 相対高度」に浮かせる(`alt_msl` は使わない)。進路・航跡・ミッション経路は地面に描く。

  - 空のミッションを開いたときは、最初に位置が分かった対象機体の上に地図を移す(1 回だけ)。
  - 離陸(NAV_TAKEOFF): ArduCopter は TAKEOFF の緯度経度を無視してその場で上昇する(`ModeAuto::do_takeoff`)。そのため空のミッションへの最初のクリックで「T = 対象機体の位置(無ければミッションのホーム)」と「WAYPOINT = クリック地点」を同時に作り、T は地図上で動かせない(高度のドラッグは可)。
  - 運用画面の 3D: 選択機のミッションをプランナーと同じ描き方(上昇角の色、ポスト、地面の円、高度に浮かせた WP 番号)で表示する。編集はできない。飛行軌跡は記録した相対高度でホーム地面 + alt_rel の高さに描く(選択機アンバー、他はアクセント)。3D では 2D のミッション線と軌跡を隠す。
  - 軌跡を残す時間(アプリ設定 › 地図表示、`map.track_minutes`、0〜120 分、既定 10): 直近この時間の点だけを残す(ホバリング中も古い点は消える)。0 で残さない。
  - 3D の進路: 対地進路ベクトルは空中の機体から伸ばし、上昇率 × 時間で高さも変える(10 s 先)。航法目標への線は飛行高度で引き、目標点に地面までのポストを立てる。3D では地表の進路線を隠す。
  - 3D の追従: 機体の後ろ上から見下ろす。地図の方位を機体の機首方位(無ければ対地進路)に合わせ、カメラの中心を地面から機体の高度(ホーム地面 + alt_rel、標高タイル未取得の間は alt_msl)へ持ち上げて、機体を画面中央に置く(MapLibre `setCenterClampedToGround(false)` + `jumpTo({elevation})`)。0.5 m / 3° / 1 m 以内の揺れは無視。追従解除・2D で元に戻す。
  - ミッションは飛行中(アーム中)でも書き込める(ArduPilot は飛行中の書き換えを受け付ける)。

## 8. ネットワーク(`view:'network'`、`glass_network*.png`、構成は 80)

- レイアウト: キャンバス(`.netmap`、ガラス面)+ 右に詳細パネル(340px)。上部に題名、概要(現場数 · 機体数 · 警告数)、凡例(インターネット / 直接波 / WebRTC / RTCM)。
- 区画(左 → 右): **現場**(現場ごと: 機体ブロック、メッシュ、メッシュ GW、現場 PC)| **インターネット** | **クラウド**(RGCS Hub)| 遠隔ユーザー・外部サービス(NTRIP)。
- 機体ブロック: 機体と機上ノードを 1 つで表す(種別アイコン、名前、SYSID バッジ、`FC · AP 1 · CAM 100 · GMB 154`、`rgcs-node · IP`)。左縁にメッシュ無線(点)、右縁から LTE。LTE 劣化はブロック枠をアンバー。
- 経路の描き分け: LTE はラベル(`LTE 84 ms · 0.2%`、劣化はアンバー)付きでインターネット区画を通って Hub へ。メッシュは機体どうし・GW を結ぶ線で、実際に使っている経路は太く流れ表示、未使用は細線、SNR 15 dB 未満はアンバー。GW の上り回線(光回線)もインターネット区画を通る。
- 地上操作(`glass_network_field.png`): 現場 PC は GW の下に「WebRTC(ローカル)」で接続し、ラベル「地上操作」。選ぶと全機体から GW までの直接波の経路を強調する。
- 遠隔ユーザー: Hub から WebRTC(紫、ラベル「WebRTC」= 映像 + DataChannel のテレメトリ)。
- クラウドは概念図: RGCS Hub 1 ブロック(アカウント・ユーザー / 機体の管理 / AWS IoT Core を応用)。詳細は右パネル。
- 選択(`glass_network_route.png`): ノード・リンク・ラベルを押すと、関係する要素以外を薄くし、右パネルに詳細を出す。機体: SYSID、ノード、クラウドまでの経路(例 `UAV-04 → UAV-03 → GW → Internet → Hub`)、通信経路、ホップ数、現場操作の経路、COMPID 表、ノードのエンドポイント表。メッシュ無線 / GW: 隣接ノードの SNR と帯域。メッシュリンク: SNR、帯域、距離、中継中の機体。LTE: 状態、遅延、ロス、帯域、電波、運ぶデータ。束ねた LTE: 機体ごとの遅延表。Hub: アカウント表と現場ごとの集計。WebRTC: 運ぶデータ、映像元、シグナリング、経路、遅延。空白を押すと Hub。
- **キャンバス**(ページはスクロールしない): ドラッグ / 2 本指で移動、ホイール・ピンチ・Ctrl+ホイールでカーソル位置を中心に拡大縮小(6〜250%)、ダブルクリックで 2 倍。右下に − / 倍率 / + / 全体表示(`.netctl`)、左下に操作ヒント。開いたとき・機体構成が変わったときは全体表示。ドラッグはクリック(選択)として扱わない。
- **表示の段階**(倍率): 55% 以上 = 詳細カード。28〜55% = 名前 + 状態色の簡易カード(`glass_network_100_compact.png`)。28% 未満 = 現場ごとの要約(名前、機体数 · LTE · 直接波 · 警告)と状態色のタイル(緑 = LTE、青 = 直接波、黄 = 警告、`glass_network_100_sites.png`)。
- **大規模**: 9 機以上の現場は 8 行の格子に並べ、メッシュは隣接機体を直線で結ぶ。LTE は現場ごとに 1 本へ束ね(`LTE × n · 中央値 ms · ⚠k`)、各機体の LTE 状態はカード右下のアンテナ色で示す。Hub・ユーザー・ラベルは全体の大きさに合わせて拡大する(`glass_network_100_detail.png`)。
- 更新: 遅延などの値は 1 Hz(WS `network_status`、50 §2.8)。

- **(2026-10-23 実装)** スタンドアロンのサーバーが持つ実データ(80 §4.1)で描き、無い要素は破線・薄色の「未構成」(`.nn.ph` / `.npl.ph` / `.ne.ph`、`styles/network.css`)で置く。値は作らない。
  - 配置: 区画は「現場 · 直接」1 つ。機体ブロックはデザインの位置、左縁の点(`r:<sysid>`)が機体の MAVLink 端。MAVLink の線(`.ne.mesh`)は各点から GW の位置に置いた **rgcs-server** カード(220×48、副題 `<listen> · スタンドアロン`)へ。リンクのピル `MAVLink · tcp:127.0.0.1:5760` は最後の機体行とサーバーカードの間の線上。映像のピル(映像 · 到達可 / 到達不可 / 確認中)はカードの右。サーバーの下に「WS(ローカル)」のピルとラベル「地上操作」、その下にクライアントのカード(220×48、58 px 間隔)。その下に「メッシュ GW · 未構成」とその「上り回線 · 未構成」。各機体の右縁から「LTE · 未構成」(9 機以上は `LTE × n · 未構成` に束ねる)→ クラウド区画の「RGCS Hub · 未構成」。ユーザー列に「遠隔ユーザー · Hub 未構成」、外部列に「NTRIP caster · 未構成」。未構成の要素も選べて、右パネルで M5 の内容を説明する。
  - 機体ブロック 2 行目は実際のコンポーネント(`FC · AP 1 · CAM 100 · GMB 154`、未受信は `FC · —`)。3 行目はノードが無いので `rgcs-node · IP` の代わりにカード接続: `MT11 · 192.168.144.25:37260 · 接続`(未接続はアンバー)/ `MAVLink カメラ · FC 経由 · CAM 100` / `カメラなし`。通信断の機体は消さず「通信断」を付ける。
  - 右パネル(機体): 状態、経路(`UAV-01 → MAVLink (tcp:…) → rgcs-server → クライアント n`)、通信経路 MAVLink 直結、クラウド経路 未構成、ハートビート、rgcs-node 未構成、カメラ、映像、COMPID 表(msg/s・ロス・最終受信)。ノードのエンドポイント表は無い。リンク: 種類・状態・接続から・受信 (推定)・ロス・再接続・最終受信・最終エラー・システム表と「詳細は MAVLink インスペクター」。クライアント: アドレス・役割・ブラウザ・接続から。
  - 既定の選択と空白クリックは `server`(デザインの既定 Hub は未構成のため)。概要は `1 リンク · 2 機体 · 1 警告 · 3 クライアント`、凡例は インターネット(未構成のみ)/ 直接波(MAVLink)/ WS / WebRTC / RTCM(未構成のみ)。
  - 警告色: 機体ブロックはリンクが `delay` / `lost` でアンバー。リンクのピルは切断かロス 3 % 超、コンポーネントの行はロス 3 % 超、映像の行は MediaMTX 到達不可でアンバー。
  - 「6 機 / 100 機(プレビュー)」切替は作らない(§10)。

受け入れ条件: 100 機・3 現場でページがスクロールせず、ホイール操作中も 60 fps 近くを保つ。機体を選ぶとクラウド経路と現場操作経路が強調される。LTE が劣化した機体はメッシュ経由で描かれる。

## 10. プロトタイプとの差(実装で変えるもの)

- プロトタイプの `simulate()`・固定チャット応答・固定「通信遅延」メッセージは実データに置換。
- パラメータは `apm.pdef.xml` から生成し、セクションごとに独立した値を持つ(プロトタイプは 3 スロット共有)。
- ログピルの文言は `command_result` と監査ログから生成。
- 映像は `<img>` ではなく WHEP の `<video>`。遅延は受信側 RTT + ジッタバッファから算出。
- メッセージの確認は警告・エラーだけ(§3.3)。確認はサーバーに記録する(`POST …/messages/{id}/ack`、50 §2.2)。プロトタイプの確認状態と履歴はクライアントの模擬データ。
- ネットワーク画面の「6 機 / 100 機(プレビュー)」切替と構成データはプロトタイプ専用。実装はサーバーの `GET /api/network` で描く(80 §4)。
- プロトタイプの撮影方向は水平画角 62°(1 倍)固定。実装はカメラごとの値を使う(40 §7.2)。
- (P1 実装)地図タイルは `config.toml` の `map_tile_url`(既定 OpenStreetMap)。追従は `setPadding` 同期で機体を可視領域中央に置く(SITL で ±0 px を確認)。
- (P1 実装)Guided 移動は機体が GUIDED でなければ `409 mode_required` を返し、UI が「GUIDED に切替」(確認付き)を出す。確認は機体ごとに初回のみ。
- (2026-10-19 変更)Guided 移動のパネルは「移動開始」ボタンだけ。押すと、GUIDED でなければ直ちに `set_mode GUIDED` を送り(2026-10-21 からモード変更に確認トークンは不要なので取得しない)、テレメトリで GUIDED になったことを確認してから(最大 5 s)目標を送る。目標へのサーバーの確認要求(`confirm_required`)には、このボタンの押下を操作者の確認として UI が自分でトークンを取得して応える。GUIDED にならなければ目標は送らず、ログに理由を出す。
- (P1 実装)未実装のナビ(全機体映像 / ミッション / AI チャット / メンテナンス)は無効表示。右パネルのカメラ帯は P2。 → AI チャットは 2026-10-24 に有効化(§3.4)。
- (P7 実装、2026-10-19)まだプロトタイプと違うもの: ネットワーク画面は無効のまま(構成データは M5、80 §4)→ 2026-10-23 に有効化し、スタンドアロンの構成(80 §4.1、§8 の実装注記)で描く。Hub・LTE・メッシュ・GW・NTRIP・rgcs-node は「未構成」。3D 地図・DSM は未実装なので、撮影方向は 2D の扇、地上投影はホーム高度の平面に投影する(地形は考慮しない)。ホームのマーカーは機体が持つミッションのホームから出す(`HOME_POSITION` は未取得)。
- (P7 実装)ログの時刻は時:分:秒。コマンドの拒否理由(MAV_RESULT)は訳して出し、単なる `failed` は「失敗」と重ねない。長いモード名(STABILIZE など)は一覧のバッジを省略表示し、ツールチップで全体を出す。
- (P7 実装)メンテナンスのタブ構成(パラメータ / 点検・校正 / 日常点検 / 飛行日誌 / 変更履歴 / アプリ設定)、右パネルのミッション進捗行、ユーザーポップオーバーの「観客用画面」は P3〜P5 の決定どおりで、プロトタイプと異なる。

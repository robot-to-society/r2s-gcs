# RGCS 設計追補 — 2026 年末デモ(MT11 一人運用 + 観客用映像)

- 版: 0.1(2026-10-17)。`docs/spec/00`〜`70` の追補。矛盾する箇所はこの文書が優先し、確定後に各仕様書へ反映する。
- 由来: 2026-10-17 のブレスト(操作者本人との対話)。「本人が決めたこと」と「筆者(Claude)の判断」を区別して書く。

## 1. 意図

年末(2026 年 12 月下旬)に、SIYI MT11 を載せた ArduCopter 機を **操作者一人** で運用するデモを行う。操作者はノート PC 1 台で **映像と地図を同時に見ながらカメラに集中** し、機体は **前日に RGCS で組んだミッション** で自動飛行する。外部モニター(HDMI 2 画面目)には **観客向けの映像 + 小さな地図 + ロゴ** を出す。Python 版の MT11 アプリではできなかった「1 つの画面で機体・ミッション・カメラ・映像・日誌を扱う」ことを、その日に見せる。

同日、国交省の **飛行日誌 3 様式**(飛行記録・日常点検記録・点検整備記録)を RGCS から出せる状態にする。飛行前点検をチェックリストとして実施・保存し、飛行後に機体からログを取り出して 1 フライトの記録として残す。

## 2. ゴール / 非ゴール / アンチゴール

### ゴール(当日できていること)
1. ログイン → 機体接続 → メンテナンス画面で状態確認・校正状態・**全パラメータの検索と変更**。
2. **飛行前点検チェックリスト** を実施して保存(= 日常点検記録 様式 2)。
3. 前日に RGCS の地図で組み、`.waypoints` に書き出して Mission Planner で確認したミッションを、機体へ書込 → 読込一致 → **AUTO 開始**。運用マップで現在 WP と進捗が見える。
4. 操作者画面: 運用マップ + MT11 映像(操作卓: ズーム / 録画 / 写真 / センター / 映像タイプ)+ ゲームパッドでジンバル。
5. **観客用画面**: 映像 + 小地図(機体追従)+ ロゴ。操作者が何をしても止まらない。
6. 飛行後: Pi 経由で DataFlash ログを取り出し、飛行記録(様式 1)に自動で日時・場所・飛行時間を埋めて保存。**3 様式を PDF / CSV で出力**。
7. 異常時: RTL / LAND / モード変更を確認付きで即時に打てる(既存 70 §1)。

### 非ゴール(デモ後に送る。設計上の席は残す)
- RGCS 内でのミッションシミュレーション(本人: 次フェーズ)
- ROI 制御器(PID)、サーマル温度オーバーレイ、AI 追跡(0x5F)、時刻同期 / SD 監視 / 自動録画
- 機体操作ジョイスティック(MANUAL_CONTROL)、3D 地図 / 地形、標高プロファイル
- edge / hub、アカウント管理の本実装、AI チャット、DataFlash の AI 解析、Tauri
- MAVLink 署名、i18n の英語完成(文言は辞書経由にしておく)

### アンチゴール(動いていても失敗とみなす)
- **観客側の映像が止まる・黒くなる**(本人が最重要と明言)。操作者のカメラ設定変更、映像タイプ切替、確認ダイアログ、録画 / 写真、ページ遷移のどれも観客側に波及してはならない。
- ミッション開始までの操作にもたついて間が空く。
- 確認ダイアログが邪魔で RTL が遅れる(確認は 1 クリック、トークンは 30 s 有効のまま)。

## 3. 制約

- 期限: 約 10 週(2026-10-17 → 12 月下旬)。実機 Pi での通しリハーサルを **12 月第 1〜2 週** に 1 回。余白はほぼ無い。
- 配置: スタンドアローン Pi 版(30 §1)。映像は MediaMTX 素通し、Pi で再エンコードしない。
- 既存の決定(00 §7)、デザイントークン(20)、コーディング規約(不変データ、200–400 行 / 最大 800、関数 50 行未満、TDD、カバレッジ 80%、`console.log` 禁止、秘密をコードに置かない、zod / `TryFrom` 検証)は全て維持。
- 現状: M1 週 2(ログイン・監査・確認トークン・コマンドキュー)が実装途中で未コミット。ここを先に閉じる。

## 4. 当日のシナリオ(本人の説明を時系列にしたもの)

**前日**: RGCS のミッション画面(2D)で WP を置き、高度・速度・コマンドを設定 → DB に保存 → `.waypoints`(QGC WPL 110)に書き出し → Mission Planner で読み込みシミュレーション → 必要なら直して保存。

**当日・飛行前**: ログイン → 機体接続を確認 → メンテナンス「パラメータ」で名前検索し必要な値を変更(確認付き、書戻し検証、履歴)→ 校正状態を確認 → 「日常点検」でチェックリストを上から実施、異常があれば備考 → 保存(実施場所・日時・実施者は自動、編集可)。

**飛行**: 運用マップでミッションを機体へ書込 → 読込一致を確認 → ARM / AUTO 開始(確認付き)→ 操作者はカメラ操作に集中。観客用モニターは映像 + 小地図 + ロゴ。

**飛行後**: DISARM 後、「飛行記録」に新しい行が下書きで現れる(日時・離着陸位置・飛行時間が自動)→ ログを機体から取り出して紐付け → 飛行概要・安全事項を記入 → 保存 → 3 様式を PDF 出力。

## 5. 決めたこと

凡例: 【本人】= ブレストで本人が決めた。【筆者】= 筆者の判断。本人は読んで覆せる。

### 5.1 観客用画面(新規 `view:'present'`、ルート `/present`)
- 【本人】内容は **映像 + 小さな地図 + ロゴ** の 3 つだけ。操作 UI、ダイアログ、ログピル、ジョイスティック表示は出さない。
- 【筆者】同じ `rgcs-server` が配信する読み取り専用ページ。ログインセッションは要求せず、**設定画面で発行する提示用トークン**(`/present?t=…`、無効化可)で守る。LAN 上の誰でも見られる状態にはしない。
- 【筆者】映像は MediaMTX から **操作者とは別の WHEP セッション** で受ける。切断時は黒画面にせず **最後のフレームを保持** し、裏で指数バックオフ再接続、画面隅に小さな「再接続中」表示のみ。WS は機体位置と現在 WP の購読だけ(10 Hz 差分は不要、2 Hz に間引く)。
- 【筆者】小地図は追従固定・操作不可・右下 320×200 程度、ロゴは左上。ロゴ画像はアプリ設定からアップロード(PNG / SVG、1 MB 以下、`data_dir/branding/`)。
- 【筆者】運用手順として、観客用はブラウザの **別窓(別プロファイル推奨)で全画面** にし、操作者のタブと描画プロセスを分ける。リハーサルの合格条件は「操作者が全操作を一巡しても観客側が途切れない」。

### 5.2 ミッション
- 【本人】**RGCS の地図上で組む**。前日作成、`.waypoints` に書き出して Mission Planner でシミュレーション。RGCS 内シミュレーションは次フェーズ。
- 【筆者】デモ版の範囲は 10 §6 のうち **2D のみ**: 左の WP 一覧、地図クリック追加 / ドラッグ移動 / 中点挿入 / 右クリック(挿入 / 削除 / 高度一括)、右の MAV_CMD パラメータ編集、サマリー(距離・時間・最大高度・警告)、Undo / Redo。3D、地形、標高プロファイル、Shift 矩形選択は後送り。
- 【筆者】ファイルは `.waypoints`(QGC WPL 110、Mission Planner 互換)を優先。`.rgcsmission`(JSON、UI 状態込み)は保存用。DB `missions` を M1 側へ前倒し。
- 【筆者】機体との往復は `rgcs-mission` の Mission Protocol 状態機械(MISSION_COUNT / ITEM_INT / REQUEST_INT / ACK、再送、タイムアウト)。書込後に読込して一致検証。開始は既存 `cmd: mission_start`(確認付き)、ArduCopter は AUTO + 先頭 TAKEOFF。運用マップに経路と現在 WP(`MISSION_CURRENT`)を表示。
- 検証は 10 §6 の通り(FENCE_ALT_MAX、先頭 TAKEOFF、ジオフェンス外は致命)。

### 5.3 カメラ・映像(M2 の中心部)
- 【筆者】デモに要るのは SIYI ドライバのうち **ジンバル速度 / センター / ズーム / 録画 / 写真 / 映像タイプ(可視 / サーマル / PiP)/ 状態取得**。能力駆動(00 §5-3)の trait と caps は仕様通りに作るが、実装するコマンドをこの範囲に絞る。
- 【筆者】映像は `rgcs-video` の WHEP 中継(50 §2.3)と遅延統計のみ。Android ソースは後送り。
- 【筆者】ゲームパッド → WS `gimbal_rate` 20 Hz、デッドマン(30 §3)は入れる。安全に直結するため省かない。

### 5.4 パラメータ(メンテナンス「パラメータ」)
- 【本人】「各制御以外にも **全てのパラメータから検索して変更** できるようにしたい」。
- 【筆者】全件テーブル(名前 / 値 / 単位 / 説明 / 範囲)+ 検索(名前・説明の部分一致、前方一致を優先)+ 変更セットのまとめ書込。説明と範囲は `apm.pdef.xml`(ArduCopter 版)を同梱して参照。書込は確認付き、書戻し検証、`param_history`、再起動要のパラメータは明示。10 §7 の「セクション + 模式図」表示は後送りし、同じテーブルの上に乗せる。
- 【筆者】全件取得(PARAM_REQUEST_LIST、1,000 件超)は Pi で保持しキャッシュ。欠落は PARAM_REQUEST_READ で補完。進捗 % を UI に出す。

### 5.5 飛行前点検チェックリスト(= 日常点検記録 様式 2)
- 【本人】「機体の設定、チェックが完了したら外装チェックなどのチェックリストを実行して保存(これが飛行前点検)」。国交省 3 様式で出す。
- 【筆者】**テンプレート**は編集可能。初期値は様式 2 の 9 項目(機体全般 / プロペラ / フレーム / 通信系統 / 推進系統 / 電源系統 / 自動制御系統 / 操縦装置 / バッテリー・燃料、各「点検内容」付き)。項目の追加・削除・並べ替えができる。機体ごとにテンプレートを選べる(設計製造者指定の項目に差し替える要領 5(2)b に対応)。
- 【筆者】**実施**は 1 回 = 1 レコード: 機体、テンプレート版、各項目の結果(正常 / 異常 / 未実施)+ 備考、特記事項(飛行後点検の結果もここ)、実施場所(手入力 or 機体 GPS から逆ジオコードなしの緯度経度)、実施年月日、実施者(ログインユーザー、編集可)。保存後は編集不可(訂正は新規実施 + 旧記録に「訂正」リンク)。
- 【筆者】チェックリスト中に「異常」があると、点検整備記録(様式 3)への下書きを 1 行作る導線を出す。

### 5.6 飛行日誌(様式 1・2・3)
- 【本人】国交省の 3 様式で出せること。
- 【筆者】**機体台帳**(`vehicles` を拡張): 登録記号(未登録なら届出番号)、種類、型式、型式認証書番号、機体認証の区分・番号、設計製造者、製造番号、**製造後総飛行時間の初期値**(RGCS 導入前の積算、分)。これらは様式冒頭の「無人航空機の概要」になる。
- 【筆者】**操縦者**(`users` を拡張): 氏名、無人航空機操縦者技能証明書番号(任意)。
- 【筆者】**飛行記録(様式 1)**: 1 行 = 1 飛行。要領 6(1)b の「電源 ON → 離陸 → 着陸 → 電源 OFF」を、サーバーでは **最初の ARM から最後の DISARM まで**(間の再 ARM は同一飛行、DISARM 後 10 分以上途絶で新飛行)と近似し、下書きを自動生成。自動項目: 飛行年月日、操縦者(当時のログインユーザー)、離陸 / 着陸の時刻(JST、分)、離陸 / 着陸場所(緯度経度 WGS84、地名は手入力欄)、飛行時間(分、切り上げ)、総飛行時間(台帳初期値 + 保存済み飛行の積算)。手入力: 飛行概要(目的の例示リストから選択 + 自由記述、特定飛行の形態チェック)、飛行の安全に影響のあった事項。**記事(不具合)**は別テーブルで、発生日 / 内容 / 処置日 / 処置内容 / 確認者。
- 【筆者】**点検整備記録(様式 3)**: 手入力の台帳。実施年月日、総飛行時間(その時点の積算を自動)、内容(部品交換名含む)、理由、場所、実施者、特記事項(次回期限)。
- 【筆者】**ログの取り出し**: `rgcs-server`(Pi)が FC から LOG_REQUEST_LIST / LOG_REQUEST_DATA で `.bin` を `data_dir/logs/<sysid>/` に保存(進捗 % を WS で)。ブラウザは Pi から HTTP で受け取る。飛行記録に 0..n 本を紐付け。デモまでの範囲では解析しない(ダウンロードと保管のみ)。
- 【筆者】**出力**: 機体ごとに期間指定で 3 様式を **PDF**(様式のレイアウトを再現、日英併記の見出し、NR. 連番)と **CSV**(1 様式 1 ファイル)。PDF 生成はサーバー側(Rust、`printpdf` 等、日本語フォントは Noto Sans JP を同梱)。【筆者】ブラウザ印刷ではなくサーバー生成にする理由: Pi からそのまま保存・配布でき、フォント差で崩れない。
- 【筆者】「飛行日誌は機体毎」(要領 4(2))に従い、画面もエクスポートも機体単位。

- 【筆者】**Mission Planner は前日のシミュレーション専用**。当日は RGCS だけを機体に接続する(第 2 GCS の同時接続はパラメータ全件取得・ミッション往復・ログ取り出しと帯域を取り合うため)。運用手順に明記する。Mission Planner で直した `.waypoints` を RGCS に読み戻す経路は 10 §6 の通り含める。
- 【筆者】**校正状態はパラメータから導いた表示のみ**(`COMPASS_OFS_*` / `INS_ACCOFFS_*` の非ゼロ、`COMPASS_CAL_FIT` 等)。「最終校正日」は点検整備記録の手入力で代替し、`MAV_CMD_PREFLIGHT_CALIBRATION` の実行はデモ後に送る。
- 【筆者】**ログは 2 経路**: (1) `rgcs-server` が FC から MAVLink で取り出す(進捗 %)、(2) SD カードから取り出した `.bin` をブラウザからアップロードして飛行記録に紐付ける。(2) を先に作り、(1) は FC↔Pi の速度が 921600 bps 以上のときだけ既定で有効にする。
- 【筆者】**観客用の帯域**: 2 本目の WHEP は LAN 前提。LTE 越しの場合は観客用を MT11 の副ストリーム(低解像度)に割り当てる案を P2 の最初に実機で確認する(本人への質問 2 の回答待ち)。

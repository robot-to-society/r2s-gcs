# プランの機体割当ボード 設計 — 2026-10-31

## 1. 目的
- 複数の機体と複数のフライトプランがあるとき、「どのプランをどの機体に書き込むか」を見て分かる形で決め、まとめて書き込めるようにする。
- いまは「開いているプラン」の各行にある小さな機体プルダウン(1 プラン = 1 機)と、比較表の「割当どおり書き込む」しかない。割当はブラウザにしか残らず、機体に今どのプランが入っているかも分からない。

## 2. ユーザーと決めたこと(2026-10-31)
| 項目 | 決定 |
|---|---|
| 見た目 | 割当ボード: プランのカードを機体のカードへドラッグ&ドロップする |
| 操作 | タッチパネルでも操作しやすくする |
| 対応 | 1 プランを複数の機体に割り当てられる。1 機体に入るのは 1 プランだけ |
| 保存先 | サーバー。機体ごとの割当と、最後に書き込んだプランと版を持つ |
| 置き場所 | フライトプラン画面の中で「編集 / 割当」を切り替えるモード |
| アーム中・飛行中 | 割当も書込もできる。書込は強い確認を挟む |
| 地図の寄せ | 割当モードを開いたら全プランと全機体が入る範囲に合わせる。プランか機体をダブルクリックするとそこに寄せる |

### 3.1 モードの切り替え
- フライトプラン画面の上部(ミッション / フェンス / ラリーのタブの並び)に「編集 | 割当」の切り替えを置く。
- 割当モードでは左右のパネルがボードになり、中央の地図はそのまま残る。
- 編集に戻ると、直前に開いていたプランの編集状態に戻る。

### 3.2 左: プランのカード
- 対象はライブラリの保存済みプラン全部(開いていないものも含む)。名前で絞り込める。
- カードに出すもの:
  - 色チップと名前
  - 距離と時間の目安
  - 割り当てた機体の数(例「2 機に割当」)。0 なら「未割当」
- 開いているプランに未保存の変更がある場合: カードに「未保存の変更があります」と出し、ドラッグはできない。割当と書込は保存済みの内容だけを使うので、保存すると割り当てられるようになる。
- 色は開いているプランの行の色と同じにする。開いていないプランには、パレットから順に色を振る。

### 3.3 右: 機体のカード
- 機体の順番: 接続中 → 未接続。その中は機体名の順。
- 上部に絞り込み欄を置く。機体名・種別・モードで絞り込む。左のプラン一覧の絞り込みとは別に動く。
- カードは最大 2 列に並べる。パネルの幅が 2 列分に足りないときは 1 列。それでも収まらなければパネルの中だけを縦にスクロールする。書込ボタンはパネルの下に固定して、スクロールしても隠れないようにする。
- ドラッグ中にパネルの上下の端へ近づくと、一覧が自動でスクロールする(§4.1)。
- カードに出すもの:
  - 種別アイコン、機体名、接続状態、アーム / モード、バッテリー残量
  - 割り当てたプランのチップ(× で外す)
  - 書込状態のバッジ(§5)
  - バッテリーの目安: 所要時間 ÷ 飛行可能時間。70% を超えるとアンバー、100% を超えると赤
  - 機体の種類に合わない内容があれば、致命的な検証結果を赤で 1 行出す。判定は `validate_for(kind)`(例: Rover に TAKEOFF なしのプラン、の逆など)

### 3.4 中央: 地図
- 割り当てたプランは行の色で描き、割当のないプランは薄く描く。
- 機体のマーカーから、割り当てたプランの開始点(最初の位置付き項目)まで、プランの色で破線を引く。
- 1 つのプランを複数の機体に割り当てたときは、機体ごとに 1 本ずつ線を引く。
- 機体カードかプランカードにカーソルを合わせる(タッチなら選ぶ)と、関係する線と経路を強調し、残りを薄くする。
- 割当モードを開いたときは、全プランと位置の分かる全機体が入る範囲に地図を合わせる。左右のパネルを避けた余白で合わせる。

## 4. 操作

### 4.1 ドラッグ&ドロップ(マウス・タッチ共通)
- Pointer Events で 1 つの実装にまとめる。
  - マウスは押して 4 px 動いたら開始する。
  - タッチは 250 ms の長押しで開始する(縦スクロールと区別するため)。開始時に軽い振動(`navigator.vibrate` が使える場合)を出す。
- ドラッグ中:
  - カードの縮小版が指(カーソル)について動く。
  - 置ける機体カードは枠を強調する。
  - 置けない機体カードは理由を出して淡くする(種類に合わない、など)。
  - パネルの端に近づくと一覧が自動でスクロールする。
- 機体カードへドロップ: その機体に割り当てる。すでに別のプランがあれば置き換え、フッターに「元に戻す」付きのお知らせを数秒出す。
- 地図上の機体マーカーへのドロップ: 段階 2(§8)。

### 4.2 タップで選んで置く(ドラッグできないとき・キーボード)
- プランカードをタップ(または Enter)すると「選択中」になり、カードが浮いた表示に変わる。
- 続けて機体カードをタップすると割り当てる。何機でも続けて割り当てられる(1 プラン → 複数機をすばやく決められる)。
- 選択は Esc、プランカードの再タップ、または何もない所のタップで解除する。
- 操作する場所はどれも 44 px 以上の大きさにする。

### 4.3 ダブルクリック(ダブルタップ)で寄せる
- プランカード: そのプランの全体(経路・フェンス・ラリー。ホームは除く)を、左右のパネルを避けた範囲に収める。編集モードの「開いているプラン」の行と同じ動き(`features/plans/frame.ts` を使う)。
- 機体カード: その機体の位置へ地図を移す。今のズームが機体が小さく見えるほど引いていれば、ズームも上げる。割り当てたプランがあれば、機体とプランの開始点の両方が入る範囲にする。
- 位置が分からない機体(未接続、または GPS 未取得)は寄せずに、カードに「位置が分かりません」を短く出す。
- タップで選んで置く操作(§4.2)とぶつからないようにする。
  - ダブルタップの 1 回目で入った「選択中」は、2 回目で外さずに残す(選択の切り替えは 1 回だけ)。
  - 機体カードのダブルタップでは割当をしない。1 回目のタップで割り当てた場合は、2 回目のタップを寄せる操作として扱い、割当は残す。
- 地図上の機体マーカー・プランの経路のダブルクリックは、今の地図の動き(ズーム)のままにする。

### 4.4 割当を外す・入れ替える
- 機体カードのプランチップの × で外す。
- 機体カードから別の機体カードへチップをドラッグすると移動になる。移動先の機体に別のプランがあれば、その機体のプランは置き換わる。
- 割当を変えるたびにサーバーへ保存する(§6)。ほかのオペレータの画面にもすぐ反映する。

## 5. 書込状態(機体カードのバッジ)
| 状態 | 条件 | 表示 |
|---|---|---|
| 未割当 | 割当なし | 灰「ここへドラッグ」 |
| 書込待ち | 割当プランと、最後に書き込んだプランまたは版が違う | アンバー |
| 一致 | 最後に書き込んだプランの id と版(`updated_at`)が割当と同じ | 緑 |
| プラン更新あり | 同じプランを書き込んだ後に、プランが保存し直された | アンバー「更新あり」 |
| 不明 | 未接続で書込記録がない、またはサーバー外で機体のミッションが変わった(§8) | 灰「?」 |
| 飛行中 | アーム中。上のどれかと併せて出す | 赤い小さな印 |

## 6. サーバー
- 新しい表 `plan_assignments`:

| 列 | 内容 |
|---|---|
| `sysid` | PK |
| `plan_id` | NULL 可。`missions.id` を指し、プランが消えたら NULL にする |
| `assigned_by` / `assigned_at` | 割り当てた人と時刻 |
| `written_plan_id` | 最後に書き込んだプラン |
| `written_plan_updated_at` | そのときのプランの版 |
| `written_at` / `written_by` | 書き込んだ時刻と人 |

- 書込記録は、保存済みプランを書いた `POST /api/vehicles/{sysid}/mission/upload {mission_id}` が照合まで成功したときに付ける。画面の未保存の内容を書いた場合は記録を消し、状態は「不明」になる。
- API:
  - `GET /api/assignments` → `[{sysid, plan_id, assigned_by, assigned_at, written}]`
  - `PUT /api/assignments/{sysid}` `{plan_id | null}` → 監査 target `assignment`
- WebSocket で `assignments` の変化を流し、ほかの画面へ反映する。
- プランを削除したら、それを指す割当は外す(`plan_id = NULL`)。

## 7. 書き込み
- ボタンは「変更のある N 機に書き込む」。対象は「書込待ち」と「プラン更新あり」の機体で、接続中のものに限る。機体カードごとの「この機体に書き込む」もある。
- 確認シートは今の「割当どおり書き込む」のシートを広げて使う。
  - 「プラン → 機体」の一覧
  - 機体に残る前のフェンス / ラリー(消す / 残す)
  - 種類が合わない機体は致命的として除外する
- アーム中の機体:
  - シートで赤い行にし、「飛行中の UAV-01 のミッションを置き換える」チェックを付けないと、その機体は対象に入らない。
  - 書込中は他の機体と同じく「検証 → 書込 → 照合」の順に進む。
  - ArduPilot は AUTO 中のミッション差し替えを受け付け、現在の WP 番号は保たれる。その旨をシートに注記する。
- 結果は機体カードのバッジに反映する(成功で「一致」、失敗は理由を出す)。

## 8. 段階
1. 段階 1(今回):
   - サーバーの割当と書込記録
   - 割当モード(左右のボード、地図の線)
   - ドラッグ&ドロップとタップで選んで置く操作
   - 状態バッジと、まとめて書き込む操作
2. 段階 2:
   - 地図上の機体マーカーへのドロップ
   - 機体のミッションがサーバーの外で変わったことの検出。ArduPilot 4.5 以降の `MISSION_CURRENT.mission_id`(opaque id)を書込時に覚え、違えば「不明」にする。

## 9. 今の仕組みとの関係
- 「開いているプラン」の行の機体プルダウンはやめる。行には割り当てた機体の名前を小さく並べ(読むだけ)、押すと割当モードを開く。
- 比較表は残す。機体の列には割り当てた機体を並べる(複数機の場合も)。「割当どおり書き込む」は割当モードの書込ボタンに一本化する。
- 編集モードの「対象機体」と「機体に書き込む」は残す(すぐ試すための 1 機書込)。保存済みで未変更のプランを書いた場合は、書込記録も付ける。

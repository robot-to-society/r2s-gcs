# P8 Operations Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The user's 2026-10-19 requests after the P7 review: course / target visualisation (2D), a selected-vehicle lock-on, a bitmask helper for parameters, a base-map choice, a configurable RGCS SYSID, and a MAVLink inspector in maintenance.

**Architecture:** Server decodes NAV_CONTROLLER_OUTPUT, POSITION_TARGET_GLOBAL_INT, HOME_POSITION and the GLOBAL_POSITION_INT velocity into `VehicleState` (diffed to the UI as today). The UI draws them on the 2D map as MapLibre layers below the DOM markers. The inspector taps every received and sent frame in `connection.rs` into a bounded in-memory table served by `GET /api/mavlink/inspector`. The GCS SYSID becomes a shared atomic read by the header builder and the mission protocol's target filter.

**Tech Stack:** Rust (axum, mavlink 0.19 with serde, sqlx), React + MapLibre GL, Vitest, Playwright.

**Spec:** docs/spec (10, 20, 30, 40, 50, 70) and the user's requests of 2026-10-19 (conversation). No prototype design exists for these features; follow the Glass design system (prototype.css classes `.g`, `.g-strong`, `.surface`, `.seg`, `.setrow`, `.switch`, `.btn`, `.btn-icon`, `.kv`, `.mono`, colours `--accent` cyan `#9cc9ff`, `--caution` amber `#f2b544`, `--ok` `#5fd39b`).

## Global Constraints

- UI copy in Japanese and English (`baseJa` / `baseEn`); no text glyph icons (Lucide only).
- No `window.confirm`; immutable UI state; files ≤ 400 lines; functions < 50 lines; TDD.
- Never hand-edit `prototype.css`; app styles go to `app.css` / feature CSS.
- 3D map is not implemented (deferred since P7): course visualisation is 2D only; 3D waits for the 3D map phase.

## Review Focus

1. Vehicle without the new streams (old firmware, rover, link just up): every new field `None`; nothing drawn; no errors.
2. POSITION_TARGET_GLOBAL_INT with lat/lon 0 or the position bits ignored in `type_mask`: no target.
3. Bitmask values above the known bits (e.g. ARMING_CHECK has unknown high bits set): unknown bits are preserved, not cleared.
4. SYSID changed while a mission upload is running / to a value equal to a vehicle's: refused (400) when it equals a known vehicle; takes effect for the next frame.
5. Inspector under a DataFlash download (hundreds of LOG_DATA/s): memory bounded (one row per (dir, sysid, compid, msg)), rate correct, the receive loop not slowed (no await on locks held across sends).

# P4 — Full parameter search and edit — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the day, the operator opens メンテナンス → パラメータ, waits for the full list (1,000+ entries with a progress bar), searches by name or description, edits a change set, writes it with a confirmation, sees the read-back verification, and finds the change in 変更履歴.

**Architecture:** The server owns a per-vehicle `ParamCache` (values + index/type, fed by PARAM_VALUE events) and a `ParamService` that runs the full download (PARAM_REQUEST_LIST, missing indexes completed with PARAM_REQUEST_READ by index) and verified writes (PARAM_SET → PARAM_VALUE echo). Metadata (`apm.pdef.json` from ArduPilot's own generator, flattened) is a static UI asset loaded lazily. The UI gets `features/params/` and a maintenance view (`view:'maint'`) with the prototype's header, 6-tab strip (パラメータ and 変更履歴 live, the rest disabled), table, change set and history.

**Tech Stack:** as P3. ArduPilot `Tools/autotest/param_metadata/param_parse.py` (run in a scratch venv with lxml) for metadata.

**Spec:** addendum §5.4, §5.9 (params rows), §7-3; docs/spec/10-screens.md §7; 50-api.md (`/params`, `/history/params`); 60-data-model.md §3.2 `param_history`; 70-safety-auth.md §1 (パラメータ書込 = 要確認).

## Global Constraints

- Same as P3 (fmt/clippy/tests green per task; immutability; wire types in rgcs-core with ts-rs; prototype class names; copy ja + en).
- Parameter write needs a confirm token for `cmd = "param_write"` (spec 70 §1) and is refused while the vehicle is armed (`409 vehicle_armed`); every change is recorded in `param_history` with `verified` and an audit row `target settings / param_write`.
- Verification tolerance: `|actual − requested| ≤ max(1e-4, 1e-6·|requested|)` (float32 round trip).
- Metadata lives in `apps/rgcs-server/ui/public/params/arducopter.json`, generated by `scripts/sync-params-meta.py` from the ArduPilot checkout; never hand-edited.

## Review Focus

1. A vehicle that answers PARAM_REQUEST_LIST with gaps (dropped frames) still reaches 100 %: missing indexes are re-requested by index, at most 20 per round, and progress reports `received/total` honestly (Task 3: `missing_indexes_are_completed_by_index`).
2. A PARAM_SET whose echo never comes ends as `verified:false` within ~5 s, is still recorded in `param_history` with `verified = 0`, and the next write is accepted (Task 3: `unanswered_param_set_is_recorded_unverified`).
3. Writing while armed, or without a valid `param_write` token, sends nothing to the link (Task 3: `armed_or_unconfirmed_write_sends_nothing`).
4. Searching "fence" matches `FENCE_ALT_MAX` by name and "geofence" by description, prefix matches sort first, and typing never blocks the UI with 5,000 metadata rows (Task 4: `search_ranks_prefix_then_name_then_description`).
5. A parameter flagged `RebootRequired` shows the reboot note in the change set and the write result (Task 4: `reboot_required_is_flagged`).

# P1 — Close M1 (auth UI, commands, map, detail panel, Guided) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish M1 so an operator can log in, see SITL vehicles on a MapLibre map, open a vehicle's detail panel, send confirmed commands and a Guided target, and see results in the footer and the audit log.

**Architecture:** The backend (`rgcs-server`, axum) already has sessions, lockout, confirm tokens, the serialized command queue and the audit log; P1 commits it, splits it into lib + bin so integration tests can build the app in-process, and adds STATUSTEXT / PARAM_VALUE routing and a Guided endpoint. The UI (React 19 + Vite, `features/<name>/` per feature, immutable reducers, `useSyncExternalStore`) gains an authenticated shell, a commands feature with confirm flow, a MapLibre map feature and a detail panel.

**Tech Stack:** Rust stable (tokio, axum 0.8, sqlx SQLite, `mavlink` crate ardupilotmega), React 19, TypeScript, Vite, vitest + Testing Library, maplibre-gl 5.x, Playwright. ArduCopter SITL binary via `scripts/dev.sh`.

**Spec:** `docs/superpowers/specs/2026-10-17-year-end-demo-design.md` (addendum) over `docs/spec/10-screens.md` §1–3, `50-api.md` §2–3, `70-safety-auth.md` §1, §5, `20-design-tokens.md`. Roadmap: `docs/plan/implementation-plan.md` §4.

## Global Constraints

- Immutable data everywhere: no in-place mutation of state objects (Rust: return new values; TS: spread / new Map). Reducers are pure.
- Files 200–400 lines (800 max); functions under 50 lines; no `console.log`; no hardcoded secrets; inputs validated (`TryFrom` / serde on the server, explicit guards on the client).
- TDD: every task writes the failing test first and commits with conventional-commit messages (`feat:`, `fix:`, `test:`, `refactor:`, `docs:`). Coverage target 80 %.
- Rust: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` must pass before each commit. `export PATH="$HOME/.cargo/bin:$PATH"` first (rustup is not on PATH).
- UI: `npm run lint`, `npm run typecheck`, `npm test -- --run` pass before each commit. npm only (no pnpm). `tsconfig` has `erasableSyntaxOnly` (no constructor parameter properties). `afterEach(cleanup)` is in `src/test/setup.ts`.
- ts-rs bindings live in `apps/rgcs-server/ui/src/shared/api/generated/` and are regenerated by `cargo test`; CI diffs them, so commit regenerated files. `u64` fields need `#[ts(type = "number")]`.
- Design tokens and class names from `20-design-tokens.md` §2–5 (`.g`, `.g-strong`, `.btn-primary`, `.seg.n5` + `.lens`, `.pop`, `.login`, `.rg-mk`, `.rg-tgt`, `.pill`, `.dev`). Colors only via CSS variables; forbidden: `#00e5ff`, `#0b1626`.
- Spec values: confirm token TTL 30 s; lockout 5 failures / 60 s; session 12 h HttpOnly SameSite=Strict; CSRF header `X-Requested-With: rgcs`; heartbeat Delay 3 s / Lost 10 s; telemetry 10 Hz; link-lost command → `503 link_lost`; confirm-required set = `arm, disarm, rtl, land, set_mode, mission_start` (+ first Guided per vehicle); map padding top 72 / bottom 60; aside 296 px (rail 60), right panel 372 px, gap 12 px; min window 1280×720.
- Dev stack: `scripts/dev.sh` (SITL tcp:5760 + server :8000 + Vite :5173, admin/admin). curl needs `-H 'X-Requested-With: rgcs'` and the session cookie.

## Review Focus

1. **Session expiry while connected** — `/ws` upgrade returns 401 after the cookie expires; the UI must stop reconnecting and show the login screen, not loop. Test in Task 3 (`store.test.ts`: `onClose` with code 4401 or an upgrade 401 → `authStore` becomes `anon` and `vehicleStore.disconnect()` is called).
2. **No GPS yet (`lat == 0 && lon == 0`, `gps.fix < 2`)** — the marker must not be drawn at 0,0 and follow must not jump there. Test in Task 6 (`markers.test.ts`: `hasPosition(v)` false → no marker; `follow.ts` ignores vehicles without position).
3. **Confirm token older than 30 s** — server returns `409 confirm_required`; the UI must re-open the confirm dialog with the message, not report success. Test in Task 5 (`useCommand.test.ts`).
4. **`command_result` racing the HTTP response** — the footer may receive the WS result before `POST command` resolves; it must dedupe by `id`. Test in Task 4 (`reducer.test.ts`: same `id` twice → one entry).
5. **Chunked STATUSTEXT (ArduPilot sends `id != 0`, `chunk_seq` 0..n)** — partial chunks must be joined, and an incomplete message flushed after 1 s rather than lost. Test in Task 7 (`statustext.rs`).

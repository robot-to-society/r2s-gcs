# P3 — Mission Planning (2D), `.waypoints`, vehicle round trip, progress — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The operator plans a mission on the RGCS 2D map the day before, saves it, exports a Mission-Planner-compatible `.waypoints`, writes it to the vehicle with read-back verification, starts AUTO (existing confirmed `mission_start`), and watches the current waypoint and remaining distance on the operations map.

**Architecture:** A new pure crate `rgcs-mission` holds the QGC WPL 110 reader/writer, the validation/summary rules and the Mission Protocol state machine (upload + download, no I/O). `rgcs-mavlink` surfaces MISSION_* frames as a `RouterEvent::Mission`; the server's `MissionHub` drives the state machine over the existing `outgoing` channel, serialises one transaction per vehicle, and broadcasts `mission_progress`. Saved missions live in a `missions` table. The UI gets `features/mission/` (immutable draft + 60-step history, MapLibre editing layer, list / editor / summary panels) behind the already-defined `view:'mission'`, and the operations detail panel gains a mission progress row and a "write mission" picker.

**Tech Stack:** Rust 1.85 workspace (axum 0.8, mavlink 0.19.1 `ardupilotmega`, sqlx SQLite, ts-rs), React 19 + TypeScript + Vite, maplibre-gl 5, zod, vitest + Testing Library, Playwright, ArduCopter SITL.

**Spec:** `docs/superpowers/specs/2026-10-17-year-end-demo-design.md` (§4 day-before scenario, §5.2, §5.7, §5.8, §5.9, §7 acceptance 2) and `docs/spec/10-screens.md` §6 (2D subset), `30-architecture.md` (`rgcs-mission`), `50-api.md` §2, `60-data-model.md` §3.8, `70-safety-auth.md` §1. Builder rulings in the addendum §9 apply (Mission Planner is for the day-before simulation only).

## Global Constraints

- Rust: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo test --workspace` green after every task. No `unwrap()` outside tests. Immutable state updates (`send_modify` / clone-and-replace) as in P2.
- UI: `npm run lint`, `npx tsc -b`, `npx vitest run` green; no `console.log`; reducers and stores are immutable (new objects, never mutation); features under `features/<name>/` with `index.ts`; files ≤ 400 lines, functions < 50 lines.
- Types that cross the wire live in `rgcs-core` with `#[derive(TS)]` and are regenerated into `apps/rgcs-server/ui/src/shared/api/generated/` by `cargo test -p rgcs-core` (never hand-edit).
- API envelope `{success, data}` / `{success:false, error:{code, message}}`; every mutating route requires the session cookie and `X-Requested-With: rgcs`; audit rows for vehicle writes (`target = "mission"`).
- `ServerMessage` is extended only by adding `#[serde(tag = "t")]` variants; existing variants keep their shape (roadmap §5).
- `.waypoints` is **QGC WPL 110**, tab-separated, line 0 = home. Lat/lon are written with 8 decimals, every other number with 6 decimals, autocontinue `1`, LF line endings. Import accepts CRLF, trailing blank lines and any decimal precision.
- Mission upload is refused while the vehicle is armed (`409 vehicle_armed`) and while another mission transaction runs for that vehicle (`409 mission_busy`). Fatal validation findings refuse the upload (`409 mission_invalid`). Protocol timeout 1.5 s per step, 3 attempts, then `504 mission_timeout`.
- Copy is Japanese first with an English twin (`shared/i18n/index.ts`); MAV_CMD identifiers are shown in monospace and never translated.
- Undo / Redo history depth is exactly 60.

## Review Focus

1. A `.waypoints` saved by Mission Planner (CRLF, trailing blank line, 7-decimal values, `DO_*` rows with lat/lon 0, a `current` flag on a row other than 0) imports with every row intact, and our export of it reloads in Mission Planner (Task 2: `imports_mission_planner_file_with_crlf_and_blank_lines`; golden fixture round trip).
2. The vehicle answers with legacy `MISSION_REQUEST` instead of `MISSION_REQUEST_INT`, asks for the same seq twice, or asks out of order; the upload still completes and no item is skipped (Task 3: `legacy_mission_request_is_answered_with_item_int`, `duplicate_request_is_answered_again`).
3. The link drops in the middle of an upload: the request ends with `504 mission_timeout` within 5 s, the vehicle's transaction lock is released, and the next upload is accepted (Task 5: `timeout_releases_the_transaction`).
4. An upload while the vehicle is armed (or a mission that fails validation) sends nothing to the link (Task 5: `armed_vehicle_refuses_upload_without_sending_frames`, `fatal_findings_refuse_the_upload`).
5. Undo after dragging a waypoint restores the exact previous coordinates; a new edit after undo clears the redo stack; the 61st edit drops the oldest snapshot (Task 7: `undo_restores_dragged_position`, `new_edit_clears_redo`, `history_keeps_sixty_snapshots`).

- Validation rules (spec 10 §6 + addendum §5.2; `code` values are the contract the UI translates):
  - Fatal `empty` (no items); Fatal `first_not_takeoff` (first item command ≠ 22); Fatal `fence_alt` (fence.enabled == Some(true) && alt_max known && any positional item in Rel frame with alt > alt_max; Abs/Ter frames are not compared — Warn `fence_frame_unchecked` instead); Fatal `fence_radius` (enabled, radius known, any positional item farther than radius from home or, without home, from the first positional item); Fatal `jump_target` (DO_JUMP param1 not in 1..=items.len()).
  - Warn `fence_unknown` (enabled is None or (enabled && alt_max None)); Warn `mixed_frames` (more than one frame among positional items); Warn `terrain_frame` (any Ter item); Warn `zero_position` (positional item with lat == 0 && lon == 0); Warn `long_flight` (stats().duration_s > 1200.0 — battery proxy, the ruling is recorded here: no endurance model exists yet); Warn `no_land_or_rtl` (last item is neither 21 nor 20).
- Stats: distance = sum of haversine between consecutive positional items (ignoring zero positions), + home→first if home set; duration = distance / max(speed, 0.1) + Σ param1 of commands 16 (delay), 19 (loiter time), 93 (nav delay when ≥ 0), 112 (condition delay); max_alt = max alt of positional items (0.0 when none).

  ```rust
  pub const STEP_TIMEOUT_MS: u64 = 1_500; pub const ATTEMPTS: u8 = 3;
  #[derive(Debug, Clone, PartialEq)] pub enum Done { Ok, Rejected(MavMissionResult), Timeout }
  #[derive(Debug, Clone)] pub struct Upload { /* sysid, target_component, items incl. home at seq 0 as MISSION_ITEM_INT frames, next_expected: u16, attempts: u8, deadline_ms */ }
  impl Upload {
      pub fn start(sysid: SysId, component: u8, mission: &Mission, now_ms: u64) -> (Self, Vec<MavMessage>);   // emits MISSION_COUNT { count = items.len()+1, mission_type 0 }
      pub fn on_message(self, msg: &MavMessage, now_ms: u64) -> (Self, Vec<MavMessage>, Option<Done>);         // MISSION_REQUEST_INT / MISSION_REQUEST { seq } → MISSION_ITEM_INT seq (any seq ≤ len, repeats allowed); MISSION_ACK → Done
      pub fn on_tick(self, now_ms: u64) -> (Self, Vec<MavMessage>, Option<Done>);                             // deadline passed → resend last frame (COUNT or last ITEM), attempts += 1; > ATTEMPTS → Timeout
  }
  #[derive(Debug, Clone)] pub struct Download { /* expected count, received: Vec<Option<MissionItem>> incl. seq 0 */ }
  impl Download {
      pub fn start(sysid: SysId, component: u8, now_ms: u64) -> (Self, Vec<MavMessage>);                       // MISSION_REQUEST_LIST
      pub fn on_message(self, msg: &MavMessage, now_ms: u64) -> (Self, Vec<MavMessage>, Option<Result<Mission, Done>>); // COUNT → REQUEST_INT 0; ITEM_INT seq → store, REQUEST_INT next; after last → MISSION_ACK accepted, Ok(mission with home from seq 0)
      pub fn on_tick(self, now_ms: u64) -> (Self, Vec<MavMessage>, Option<Result<Mission, Done>>);
  }
  pub fn item_to_int(seq: u16, sysid: SysId, component: u8, item: &MissionItem, current: bool) -> MISSION_ITEM_INT_DATA;  // x = (lat*1e7).round() as i32, y likewise, z = alt, frame = MavFrame from mav id
  pub fn int_to_item(d: &MISSION_ITEM_INT_DATA) -> Option<MissionItem>;                                      // None for unknown frame
  pub fn mission_from_items(home: Option<MissionItem>, items: Vec<MissionItem>) -> Mission;                   // name "", home → Home
  ```

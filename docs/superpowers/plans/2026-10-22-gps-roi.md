# GPS ROI (Computed) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The MT11 gimbal keeps pointing at one of 10 GPS presets per vehicle. This is spec 40 §4, "GPS ROI (Computed)". The work has three parts:
- Port the Python app's geo / PID / ROI controller to Rust and run it on the server per vehicle. It sends 0x07 at 10 Hz in rate mode, or 0x0E in angle mode.
- Store the presets and control parameters per vehicle and expose them through REST.
- Add the UI: the camera-settings ROI tab, the map markers and sight line, the cockpit ROI chips, and the ROI name in the status row and card. Joystick buttons `roi_1`..`roi_10` / `roi_stop` work too.

**Architecture:**
- **Pure controller.** The controller lives in `crates/rgcs-camera/src/roi/` as `geo.rs`, `pid.rs` and `controller.rs`. It is an immutable state machine: `(state, inputs, now_ms) → (state, camera commands, status)` with no I/O. The Python tests become its `#[test]`s.
- **One task per active vehicle.** `apps/rgcs-server/src/roi.rs` (`RoiHub`) owns one tokio task per active vehicle. Each tick the task reads the router's `VehicleState`, the GLOBAL_POSITION_INT age and the camera's attitude watch. It feeds them to the controller and sends the resulting commands through `CameraManager`. While active it broadcasts `roi_status` at 2 Hz.
- **Single writer.** Start / stop / config / target changes and every tick go through that one task, so a stop can never be followed by a stale command. This replaces the Python generation counter.
- **Cancellation.** Manual input cancels ROI in three places: the WebSocket gate actions, the REST camera commands and camera profile reloads.

**Tech stack:** Rust (tokio, axum, sqlx SQLite, ts-rs), React 19 + TypeScript (vitest, @testing-library, zod), MapLibre GL 5.

## Rulings (spec conflicts / open questions decided here)
1. **ROI is not a `CameraCommand`.** Spec 40 §1.2 lists `RoiStart` / `RoiStop`, but spec 50 has dedicated REST routes.
   - Start and stop go only through `POST …/roi/start|stop` and the `RoiHub`.
   - Reason: `CameraCaps::supports` stays a pure per-driver check, and the audit uses target `roi`.
2. **`RoiStatus` travels only in the WS `roi_status` frame.** It is not inside `CameraState`; spec 40 §1.3 is superseded by spec 50 §3.1.
   - No snapshot field. A reconnecting client learns the state within 0.5 s.
   - When inactive the UI treats the status as "none".
3. **`roi_control` is per vehicle** (PK `sysid`). The API is per vehicle, but spec 60 lists no key.
4. **Validation lives in `rgcs-core::roi`**, next to `CameraProfile::validate`, which the server already calls.
   - `rgcs-store::roi` only persists.
   - This deviates from the spec 40 §7 port-table location (`rgcs-store::roi`). The behaviour is identical.
5. **The Python one-time import (60 §5, line 153) is out of scope.** It does not cover `roi_config.json` / `joystick_config.json`. The spec 60 acceptance line about it stays open.
6. **What counts as manual input that cancels ROI:**
   - WS `gimbal_rate` with max(|yaw|, |pitch|) ≥ 5;
   - REST `gimbal_center`, `gimbal_angle`, `gimbal_mode`;
   - a camera profile PUT (the driver is rebuilt).
   - "AI 追跡開始で ROI 解除 / ROI 開始で AI 追跡解除" has no code path yet (no AI commands exist in Rust). `RoiHub::stop(…, StopReason::Manual)` is the hook the AI work will call. This is noted in spec 40.
7. **Joystick zeros while ROI is active are dropped.** This covers every zero that the WebSocket gate sends for a vehicle while its ROI is active, including:
   - forwarded (0, 0) frames;
   - deadman / select / close `Action::Zero`.
   - Reason: the ROI loop owns the gimbal and has its own staleness rules. A joystick zero would only make it stutter.
   - The deadman `input_state: lost` reply is still sent.
8. **Stop always sends speed 0, in both modes, even when still.** The spec says "必ず", and it costs nothing.
   - Operator / target-removed / shutdown stops: one immediate zero + 2 resends.
   - Manual cancel: a single zero, no resends. Resends would fight the operator's stick, which is already sending speeds.
9. **No watchdog thread.** Every camera send in the task is wrapped in `tokio::time::timeout(SEND_TIMEOUT = 200 ms)`. A timeout counts as a failed send: the controller halts and reports `send_failed`.
10. **Error strings are fixed codes, translated by the UI:**
    - `no_position`, `position_stale`, `heading_unknown`, `target_too_close`;
    - `no_attitude`, `invalid_angles`, `follow_failed`, `send_failed`;
    - `camera_offline`, `waiting`.
    - Following spec 40 §4, ROI is not auto-cancelled on these errors.
11. **A target is "set"** when `name.trim()` is non-empty and not (lat == 0 && lon == 0).
    - Starting an unset target → `409 roi_target_unset`.
    - A targets PUT that unsets or removes the active slot stops ROI.
    - Changing its coordinates keeps it running with the new point.
12. **Position age comes from the router's per-message timestamps.** `Router::message_age_ms(sysid, 33)` (GLOBAL_POSITION_INT) uses a router-held "latest clock". Accuracy is ≤ 1 s when the link is totally silent (the router ticks at 1 Hz) and exact otherwise.
13. **Attitude freshness without a new driver API.**
    - The task stamps `attitude_at = now − state.gimbal.age_ms` whenever the camera watch reports a change.
    - During ROI it requests 0x0D every rate-mode step through a new `Camera::request_attitude()`. That method defaults to `Unsupported`.
14. **Map pick for 「地図で指定」:**
    - Ground elevation comes from the Terrarium DEM (`settings.terrain_tiles`, `TerrainSampler`), with a 3 s wait for the tile.
    - Fallback is the selected vehicle's `home.alt` (MSL), else 0. Both fallbacks show a caution hint.
    - The name defaults to `ROI n` when empty (prototype `pickRoi`).
    - The sheet's drafts survive the pick round-trip because they are lifted to a settings-flow hook.
15. **Where things are shown:**
    - The ROI chip row lives in the cockpit `CamBar` (spec 10 §4.2, prototype line 788), not the detail-panel `CameraStrip`.
    - The detail-panel status row shows only the ROI name (10 §3.3 item 4).
    - Map markers show the selected vehicle's named presets.
16. **ROI tab when the camera cannot do ROI.** With `caps.roi === 'none'`, the ROI tab button stays in the 4-wide segmented control but is disabled (`.off`, title = `roiUnsupported`), like the Video tab today.
17. **CSV header row:** a first non-blank line whose lat and lon are both non-numeric is a header. Rows beyond 10 are not validated; they are counted as skipped. The import replaces all 10 slots, and slots without a row become empty (Python `toRoiTargets`). MP `poi.txt` import is out of scope (it has no altitude).
18. **Server restart / shutdown:**
    - The ROI state is not persisted. A restarted server comes up with ROI inactive.
    - Graceful shutdown stops every active ROI with zeros.
    - After boot, every driver whose caps have `gimbal.rate` gets one `GimbalRate{0,0}` once it first reports `connected`. Without it, a gimbal left turning by a crash would keep turning.

## Review Focus (untested-in-isolation failure modes most likely to bite)
1. **Vehicle position stale while the link still carries other messages.** For example, EKF / GPS loss while heartbeats continue.
   - `message_age_ms(…, 33)` must grow, the controller must halt with `position_stale`, and `roi_status.error` must show it.
   - Tested: Task 5 router test, Task 3 controller test. The full chain is checked live in Task 9.
2. **Heading unknown (hdg = 65535) mid-flight:**
   - The decoder maps it to `None`; the controller halts with zero.
   - The UI sight line must fall back to no line rather than throw (`gimbalPose` already requires `hdg`).
3. **Target < 3 m** (the vehicle flies over the preset): a zero, an error `target_too_close`, ROI stays active, and it resumes on its own when the vehicle moves away.
4. **Manual input cancel races:**
   - A stick frame ≥ 5 arriving while a tick is mid-send must cancel.
   - The cancel's single zero must reach the gimbal before the manual frame.
   - The manual frame must not be dropped.
   - Order is guaranteed only because `RoiHub::stop` awaits the task's acknowledgement before `perform` forwards. Verify this in the `ws.rs` change.
5. **Server restart / driver reload while active:**
   - A profile PUT stops ROI before `reload`.
   - A crash leaves the gimbal turning until the boot zero (ruling 18).
   - Verify that the boot zero does not fire for `none` / MAVLink (caps without rate) and fires only once per install.

**Algorithm.** The tests do not fully determine it, so it is fixed here. `step` while active:
1. **Resends:** if `zero_resends > 0`, push `GimbalRate{0,0}` and decrement. This also happens while inactive.
2. **First step:** if `last_follow_ms` is `None`, push `GimbalMode{Follow}` first and set `last_follow_ms = now`.
3. **Goal (decimated):** if the goal is due (`target_at` is `None` or `now − target_at ≥ 1000 / target_rate_hz`), recompute it.
   - `raw` = `to_gimbal_angles(look_angles(own, target), hdg, yaw_offset)`.
   - The error rules run in order: no fix → `no_position`; `age_ms > 2000` → `position_stale`; `hdg None` → `heading_unknown`; `distance < 3` → `target_too_close`; non-finite → `invalid_angles`.
   - On success, smooth the goal: yaw with `wrap = true`, pitch plain. dt = now − target_at in s, or 0 on the first goal. Set `bearing` / `elevation` / `distance` / `yaw_cmd` / `pitch_cmd` in the status.
4. **Goal error or no goal:** halt (zero only if `last_speed ≠ (0,0)`) and set `status.error`. The step ends here.
5. **Rate mode:**
   - Halt with `no_attitude` when the attitude is missing, older than 500 ms, or non-finite.
   - dt = min(now − control_at, 2 periods), or 1 period on the first step.
   - Errors: `stable_yaw_error(goal.yaw, att.yaw, prev_yaw_error)` and `goal.pitch − att.pitch`. Pass both through `deadband_with_hysteresis`.
   - PID per axis. Gains: `(kp, ki, kd, i_limit = max_speed / 2, out_limit = max_speed)`. An axis with error 0 outputs 0 and resets its `PidState`.
   - `speed = (clamp(round(−out_yaw), −100, 100) as i8, clamp(round(out_pitch)) as i8)`.
   - Push `GimbalRate` if `speed ≠ (0,0)` or `last_speed ≠ (0,0)`. A non-zero speed clears pending resends.
   - Set `request_attitude = true`.
6. **Angle mode:**
   - `yaw = stabilize_yaw(goal.yaw, last_sent.yaw)`.
   - If there is no previous angle, or max(|Δyaw|, |Δpitch|) ≥ deadband, push `GimbalAngle{yaw_deg, pitch_deg}` (cast to f32) and record it.
7. **Follow re-assert:** if `now − last_follow_ms ≥ 5000`, push `GimbalMode{Follow}` after the motion command and update `last_follow_ms`.

The status always mirrors the speeds sent. Any halt shows `speed_yaw` / `speed_pitch` as `Some(0)`.

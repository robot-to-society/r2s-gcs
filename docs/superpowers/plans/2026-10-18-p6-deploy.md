# P6 Deployment + Docker Pi Equivalent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `rgcs-server` as one aarch64 binary with the UI embedded, an idempotent `deploy/install.sh` (systemd, Python-service takeover, upgrade with automatic rollback), and a Docker "Pi equivalent" (Debian bookworm arm64 + systemd + MediaMTX + test video + MT11 simulator + FC link over UDP or a serial pty) on which the whole deployment and the existing SITL acceptance scripts run end to end before the real-hardware rehearsals.

**Architecture:** The UI is compiled into the binary with `include_dir` behind an `embed-ui` feature; `config.toml` `ui_dir` still overrides it. The Pi binary is built natively inside a `rust:bookworm` arm64 container (Apple Silicon → no emulation; bookworm glibc = Raspberry Pi OS). The test Pi is a privileged Debian bookworm container running systemd as PID 1; MediaMTX, the ffmpeg test pattern and the MT11 simulator share its network namespace so everything is on `127.0.0.1` exactly as on the real Pi. The FC link is a `socat` bridge from the host's ArduCopter SITL (`tcp:5760`) to either `udp 127.0.0.1:15555` (Rpanion mode) or a pty `/dev/ttyFC` (serial mode).

**Tech Stack:** Rust (axum 0.8, include_dir 0.7, mime_guess 2), bash, systemd, Docker Desktop (linux/arm64, compose v2), MediaMTX, ffmpeg, socat, iproute2 `tc netem`, Playwright.

**Spec:** `docs/plan/implementation-plan.md` row P6 (`include_dir` で UI 埋め込み、`deploy/install.sh`、実 Pi + 実 FC + MT11、LTE 越し); `docs/spec/30-architecture.md` §1 (aarch64 single binary, `rgcs-server.service` replaces `mt11-camera-ui.service`, 同時起動禁止), the Pi setup procedure and the performance table; addendum `docs/superpowers/specs/2026-10-17-year-end-demo-design.md` §7-1 (観客用映像が 1 秒以上止まらない) and §9 (log fetch only at ≥ 921600 bps by default); the user's request of 2026-10-18 (「Dockerでラズパイ環境を構築してテスト」).

## Global Constraints

- Target: `aarch64-unknown-linux-gnu`, glibc ≤ 2.36 (Raspberry Pi OS bookworm). Build inside `rust:<stable>-bookworm` linux/arm64; never require QEMU.
- Paths on the Pi: binary `/opt/rgcs/bin/rgcs-server` (previous kept as `rgcs-server.prev`), config `/etc/rgcs/config.toml`, data `/var/lib/rgcs`, unit `/etc/systemd/system/rgcs-server.service`, service user `rgcs` (groups `dialout`).
- `rgcs-server.service` and `mt11-camera-ui.service` must never run together (spec 30 §1: MT11 TCP is single-client, both bind :8000).
- Default link stays `udpin:127.0.0.1:15555` (Rpanion). Default listen `0.0.0.0:8000`.
- Development keeps the local SITL binary (`scripts/dev.sh`); Docker is added for deployment testing only (ruling: amends roadmap §2「docker-compose は作らない」).
- The host SITL accepts ONE TCP client: stop `scripts/dev.sh` before the Pi harness connects.
- Files ≤ 400 lines (800 max), functions < 50 lines, TDD, no secrets in files, conventional commits with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, never stage `.claude/`.

## Review Focus

1. **Upgrade over a live install** must keep `/etc/rgcs/config.toml` and `/var/lib/rgcs` (database, logs) untouched — `accept-deploy.sh` step `[4] upgrade keeps config and data`.
2. **A new binary that does not come up healthy** must be rolled back automatically, leaving the old version serving — step `[7] broken upgrade rolls back`.
3. **The Python camera service still enabled** (both on :8000, both talking to the MT11) must be stopped and disabled by the installer and blocked by `Conflicts=` — step `[1] fresh install takes over from the Python service` asserts `systemctl is-enabled mt11-camera-ui` = `disabled`, and that starting the Python unit by hand stops `rgcs-server` (`Conflicts=`), so the two never run together.
4. **Serial FC link** must work for the unprivileged service user and log fetch must follow the baud rule — step `[6] serial link` (57600 → `log_fetch_disabled`, 921600 → enabled).
5. **Reboot / restart while armed** must bring the service back enabled and adopt the open flight — steps `[5] restart while armed` and `[8] reboot`.

Also pinned: SPA deep links (`/present?t=…`, `/mission`) reload from the embedded UI (Task 1 test `embedded_ui_serves_spa_routes_and_assets`); `--version` works without a config file (Task 2).

**Interfaces:**
- `deploy/install.sh [--binary PATH] [--rollback] [--health-timeout SECS(30)]` (root): validates the binary (`file` says ELF aarch64 or `--version` runs), creates user `rgcs` (`--system --home /var/lib/rgcs --shell /usr/sbin/nologin`, `usermod -aG dialout`), dirs (`/opt/rgcs/bin` 0755, `/etc/rgcs` 0755, `/var/lib/rgcs` 0750 rgcs:rgcs), installs the binary atomically (`install -m 0755` to `.new`, keep current as `.prev`, `mv`), writes `/etc/rgcs/config.toml` from the example only when missing, stops + disables `mt11-camera-ui.service` when it exists (prints what it did), installs the unit, `daemon-reload`, `enable`, `restart`, polls `http://127.0.0.1:8000/api/health` until 200; on timeout restores `.prev`, restarts, prints `ROLLED BACK` and exits 1. `--rollback` swaps `.prev` back and restarts.

# AI 緊急介入（実験機能） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v1 of the AI 緊急介入 experimental feature (spec `docs/superpowers/specs/2026-10-24-ai-intervention-design.md` v0.3). The AI's main job is to spot the first signs of an anomaly early and to give the human operator as much support as possible:
- **Monitoring.** The server watches every connected vehicle's telemetry all the time and runs deterministic detectors. The first event is **toilet-bowl** (spec §5.1): sign A, plus sign B or sign C.
- **Alerting.** It warns with sound plus screen: the vehicle is highlighted, and a banner reads 「UAV-03 トイレットボウルの兆候 — 手動で引き継いでください」. The alert also goes into the message log and the AI chat.
- **Acting (L2 / L3 only).** At L2 or L3 it switches the vehicle to a mode with no position hold: Copter `ALT_HOLD`, QuadPlane `QHOVER`.
  - L2 waits through a 5 s countdown that anyone can cancel (取り消し). L3 acts at once.
  - Pilot takeover is detected from `RC_CHANNELS` stick movement or from any operator GCS command.
  - If nobody takes over, the AI **never acts again** on that vehicle in that flight. The warning stays up.
- **Opt-in.** Everything stays off until an admin turns on 実験機能 › AI 緊急介入 through an in-app 3-part consent dialog:
  - 1 = continuous telemetry monitoring (required);
  - 2 = sending data to external services;
  - 3 = automatic operation risk (needed for L2 / L3).
- **External factors (spec §5.3–§5.5).** The server reads Open-Meteo, JMA AMeDAS, NOAA SWPC (Kp observed / 1-minute / forecast / alerts), GFZ Kp (optional) and OpenWeatherMap (optional, needs a key).
  - It also computes WMM declination, sunrise / sunset and vehicle-measured wind / GNSS locally.
  - Deterministic rules fuse all of this. External factors alone never trigger an action. They raise the sensitivity of the vehicle-side signs.
  - A dedicated settings page 「外的要因データ」 manages the sources.
- **Records.** Every decision is audited (`target = 'ai_intervention'`) and stored as a replayable decision record.

**Architecture:**
- **New pure crate `crates/rgcs-guard`** (spec §7.1). It has no I/O, no async, no server types, and depends only on `serde`. It is written so a future onboard node or FC with a local LLM can link it.
  - `sample.rs`: `Sample` (one 10 Hz telemetry point), `Airframe`, `FlightMode`.
  - `geo.rs`: local ENU, angle wrap, Kåsa circle fit.
  - `toilet_bowl.rs`: `ToiletBowlConfig` and `ToiletBowlDetector`, which push a sample and return `(Self, Verdict)`.
  - `sensitivity.rs`: `ExternalContext` → effective thresholds.
  - `takeover.rs`: `RcWatch`, an RC baseline plus deviation check.
  - `intervention.rs`: a pure per-vehicle state machine. It takes `Input` and returns `(Self, Vec<Effect>)`.
  - `record.rs`: `DecisionRecord` and `replay(record) -> Verdict`.
- **New pure crate `crates/rgcs-env`** (rules and parsers only; fetchers live in the server).
  - `reading.rs`: `Reading`, `SourceId`, `SourceClass`, `FactorKind`.
  - `parse/*.rs`: one `fn parse(body: &str, fetched_ms: u64) -> Result<Vec<Reading>, ParseError>` per source.
  - `fusion.rs`: `fuse(readings, thresholds, now) -> Vec<FusedFactor>`.
  - `location.rs`: rounding.
  - `sun.rs`: NOAA sunrise / sunset.
  - `magnetic.rs`: WMM through the `world_magnetic_model` crate.
- **`rgcs-mavlink`:** `guard_tap.rs` turns `EKF_STATUS_REPORT`, `RC_CHANNELS`, `WIND`, `GLOBAL_POSITION_INT` (vx / vy), `MISSION_CURRENT` and `EXTENDED_SYS_STATE.vtol_state` into a `GuardFrame`.
  - The frames go out on a new **lossy** `broadcast` channel, `LinkChannels.guard`. The guard never back-pressures the link, unlike the `events` mpsc.
  - `interval.rs` `WANTED` gains `EKF_STATUS_REPORT`, `RC_CHANNELS` and `WIND`.
- **Server (`apps/rgcs-server`):**
  - `guard_hub.rs`: `GuardHub` (cloneable). It runs one detector plus intervention machine per sysid, fed from the guard tap and the router's `watch` state. It also:
    - emits `ServerMessage::GuardAlert` frames and message-log rows;
    - executes `SetMode` through `app.queue` (with the `commands::precheck` / `commands::queued` path) only when the policy allows;
    - tracks takeover;
    - writes decision records and audit rows.
  - `guard_api.rs`: `GET/PUT /api/guard/settings`, `GET /api/guard/alerts`, `POST /api/guard/alerts/{id}/cancel`, `GET /api/guard/decisions`.
  - `env_hub.rs` / `env_fetch.rs` / `env_api.rs`: per-source fetch scheduler (`reqwest`, no redirects, timeouts), status, fusion, the `ExternalContext` for `GuardHub`, and `GET /api/env/factors`, `GET/PUT /api/env/settings`, `GET /api/env/sources`, `PUT /api/env/sources/{id}`, `POST /api/env/sources/{id}/fetch`.
  - `commands.rs` / `guided.rs`: an accepted operator send calls `app.guard.note_operator_command(sysid)`, which counts as takeover.
  - `ai_tools.rs`: two new read-only tools.
- **Store:**

  - `app_settings` keys `guard.settings` and `env.settings` (JSON).
- **Core types (`rgcs-core/src/guard.rs`, `rgcs-core/src/env.rs`, ts-rs):** `GuardLevel`, `GuardConsent`, `GuardSettings`, `GuardAlert`, `GuardPhase`, `GuardSigns`, `EnvFactor`, `EnvSummary`, `EnvSourceStatus`, `EnvSettings`, `EnvThresholds`. `ServerMessage` gains `GuardAlert { alert }` and `EnvSummary { summary }`.

## Global Constraints
- TDD: every test is written and seen failing first.
- Immutable state: never mutate shared objects. In Rust, return new values where the codebase does (`fn push(&self, …) -> (Self, …)`, `..self.clone()`).
- Files ≤ 400 lines typical, 800 max. Functions < 50 lines.
- UI:
  - single quotes, no semicolons, never run prettier;
  - Lucide icons only (`shared/ui/icons.tsx`), never text glyphs (no `✓`, `×`, `→` as icons);
  - never hand-edit `styles/prototype.css`;
  - no `window.confirm`.
- UI type check: `npx tsc --noEmit -p tsconfig.app.json`, run from `apps/rgcs-server/ui`.
- UI tests: `npx vitest run <paths>`.
- Rust:
  - `export PATH="$HOME/.cargo/bin:$PATH"`;
  - `cargo test -p <crate>`;
  - `cargo clippy --workspace --all-targets -- -D warnings`.
- ts-rs bindings (`apps/rgcs-server/ui/src/shared/api/generated/`) are committed.
- Commit messages are conventional (`feat(...)`) and end with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never commit `.claude/`, `auto.crt`, `auto.key`.
- Never send vehicle commands or write vehicle params to the dev stack (ports 5760-5793, 8000, 5173, 14550, 14551, 37260). Live checks run only against a scratch server (8110), a scratch Vite (5181), scratch SITLs (`-I6` copter on tcp:5820 / RC udp:5561, `-I7` QuadPlane on tcp:5830 / RC udp:5571) and a scratch fake env server (18111) (Task 11).
- Never use `pkill` / `killall` / pattern kills. Stop only processes you started, by the PID you recorded (`$!`).
- **Never log or return API keys.** Env-source keys come only from config / env vars (`Secret` from `rgcs-ai`, redacting `Debug`). The UI sees `key_configured: bool` and `key_hint: "…ab12"` (the last 4 chars) only. A test asserts the key text is absent from every `/api/env/*` body, from `format!("{config:?}")`, and from the fetch error strings.
- **No real internet in tests.** Parsers are tested against committed fixture files. Fetchers are tested against a local axum fake on `127.0.0.1:0`, with every source base URL injectable through `EnvEndpoints`. No test uses a default (real) host. A test asserts `EnvEndpoints::default()` is never used under `#[cfg(test)]`: the test helper builds endpoints only from the fake's URL.
- **Never send vehicle commands to the dev stack.** That includes the guard's own `SetMode`. While developing, leave the guard disabled on the dev stack: the setting is off by default, and nothing in this plan turns it on there.
- **SITL fault injection only on scratch SITL instances.** `SIM_MAG*`, `COMPASS_*`, `EK3_*`, `SIM_WIND_*` and `ARMING_CHECK` are written only through the scratch server (8110) to `-I6` / `-I7`. `tests/sitl/guard_toilet_bowl.py` refuses to run when `--server` is port 8000 or when `--sitl-port` is in 5760-5793.
- **The guard never sends anything except `SetMode {ALT_HOLD | QHOVER}`.** It never arms, takes off, writes params, clears failsafes, moves out of the fence or overrides a human (spec §2). There is exactly one call site that enqueues a guard command: `guard_hub.rs` `execute()`.

## Rulings (spec gaps / open questions decided here)
1. **Off means off.** With 実験機能 › AI 緊急介入 disabled, `GuardHub` runs no detector, raises no alert, and `EnvHub` fetches nothing external. Sun and WMM stay local and are shown only on the 外的要因データ page.
   - We read spec §3's last line 「オフのとき…警告と提案だけ」 as the existing AI chat proposal behaviour.
   - Consent 1 is required to enable. Consent 2 off → no external fetch at all: no partial fetch of the location-free SWPC either, because consent 2 covers outbound data in general. Consent 3 off → levels are capped at L1, and the UI disables L2 / L3.
   - Disabling clears all three consents. Re-enabling asks again.
   - A disable during a countdown cancels it (phase `Cancelled`, by `disabled`).
2. **Detection runs per sample, on a pure detector.** `ToiletBowlDetector::push(&self, s: &Sample, cfg: &EffectiveConfig) -> (Self, Verdict)` keeps a `VecDeque<Sample>` window.
   - `Suspect` (A only) is recorded but never alerted: spec 「1 兆候だけでは発動しない」.
   - Default values are the fixed values above. Task 11 may tune them from scratch-SITL data, but only in a commit that also updates the synthetic tests.
3. **Monitored modes.**
   - Copter: `LOITER`, `POSHOLD`, `GUIDED` (target fixed), `AUTO` (only while `nav.wp_dist ≤ 3 m` at the window start and the mission seq is unchanged, as the 「WP 待機」 proxy).
   - QuadPlane: `QLOITER`, and `GUIDED` with `vtol_state == MC`.
   - Everything else is not monitored, `CIRCLE` included (spec §5.1). A monitored-mode exit clears the window.
4. **The guard's only action and its preconditions.** `SetMode` is sent only when all of these hold at execution time (re-checked after the countdown):
   - enabled, with `consent.auto_ops`;
   - level L2 (countdown elapsed) or L3;
   - verdict still `Detected` within the last 1 s;
   - the vehicle is still armed and in a monitored mode;
   - link not lost (`commands::precheck`);
   - no takeover;
   - no earlier action this flight;
   - no countdown cancel.
   The queue outcome becomes `Executed` (ok) or `Refused` (failed / timeout). Either way the machine then goes hands-off until disarm (fixed values: Intervention).
5. **Takeover sources.**
   - RC: `RcWatch`, baseline = median of the last 1 s before the alert. With no `RC_CHANNELS` for > 2 s, the UI shows 「RC 未受信 — GCS 操作で引き継ぎ」.
   - GCS: `commands::command` (after a successful `enqueue`) and `guided::guided` (after acceptance) call `app.guard.note_operator_command(sysid)`.
   - Mode: a mode change the guard did not command.
   - The guard's own `SetMode` goes straight to `app.queue` and never passes through `commands::command`, so it never counts as a takeover.
6. **Cancel (取り消し).** Any signed-in user may cancel a countdown: `POST /api/guard/alerts/{id}/cancel`, audited. A cancel stops that alert's action for the rest of the flight. The warning stays until the alert clears or is taken over.
7. **Alert surfaces.**
   - The WS frame `guard_alert` carries the full `GuardAlert` on every phase change, plus a 1 Hz re-send while a countdown runs.
   - `GET /api/guard/alerts` returns the active alerts for a fresh client.
   - A message-log row goes out on detection, executed, cancelled and unanswered.
   - The UI highlights the vehicle by OR-ing `guardActive` into the `warn` visual of the map marker and the list row.
   - Sound is a UI-side Web Audio tone (no audio assets). Each browser can mute it in the banner (`IconVolumeOff`), saved in `localStorage` with try/catch.
8. **Audit and records.** Settings changes and actions go to `audit_log` with `target = 'ai_intervention'`. Decision records go to `guard_decisions`: one row per phase change, `flight_id` = `FlightTracker`'s open flight for the sysid (add `open_flight(sysid) -> Option<i64>`), pruned to 5 000 rows. `GET /api/guard/decisions?sysid=&limit=` (admin) returns them. A replay test re-runs `rgcs_guard::replay`. A replay UI is out of scope.
9. **Telemetry tap, not router events.**
   - Guard frames go through `LinkChannels.guard: broadcast::Sender<GuardFrame>` (capacity 512). `connection.rs` publishes them like `publish_payload`, so a slow guard drops frames instead of stalling the link.
   - `GuardHub` drops frames whose `compid != router.fc_component(sysid)`.
   - Mode, kind, vtol, target, nav and armed come from `Router::subscribe(sysid)` `watch` receivers. No router lock is taken per sample.
   - `WANTED` gains `(MSG_ID_EKF_STATUS_REPORT = 193, 500_000)`, `(MSG_ID_RC_CHANNELS = 65, 200_000)` and `(MSG_ID_WIND = 168, 1_000_000)`. `WIND` is added to `ONCE` because only ArduPilot sends it.
10. **Source choices** (spec §5.4 table; terms are noted on the settings page):
    - **Open-Meteo:** `GET {base}/v1/forecast?latitude=&longitude=&current=temperature_2m,precipitation,wind_speed_10m,wind_gusts_10m,wind_direction_10m&hourly=wind_speed_80m,wind_speed_120m,precipitation_probability&forecast_hours=3&wind_speed_unit=ms&timezone=UTC&models=best_match`. The free API is for non-commercial use, so the page says so. Setting a key (config `open_meteo_api_key_env`) switches the host to `customer-api.open-meteo.com` and adds `&apikey=`.
    - **JMA AMeDAS:** `GET {base}/bosai/amedas/data/latest_time.txt`, then `/bosai/amedas/data/map/{YYYYMMDDHHMMSS}.json`, plus `/bosai/amedas/const/amedastable.json` (cached 24 h). Only these are sent, never coordinates; the nearest station within 30 km is picked locally.
      - Read `wind`, `windDirection`, `temp`, `precipitation10m` (×6 → mm/h). Only quality flag 0 counts.
      - Attribution 「出典: 気象庁ホームページ」 is shown with every reading.
      - The `bosai` JSON is not a contractual API, so a format change is a source failure (`parse`), never a crash.
    - **JMA 雷・降水ナウキャスト:** **out of scope for v1.** It is served only as PNG map tiles with a colour legend, not as data. Open-Meteo precipitation and AMeDAS 10-minute precipitation cover precipitation for now.
    - **NOAA SWPC:** `products/noaa-planetary-k-index.json` (`Observed`), `json/planetary_k_index_1m.json` (`estimated_kp`, `Nowcast`), `products/noaa-planetary-k-index-forecast.json` (`Forecast`, max over the next 24 h) and `products/alerts.json`.
      - Alerts are listed as notes with `product_id` + `issue_datetime`; the message is `untrusted_text` and is not used for levels.
      - The Kp parsers accept both the header-row array form and the array-of-objects form, because SWPC has changed formats. There is one fixture per form.
    - **GFZ Kp (optional, off):** `GET {base}/app/json/?start=&end=&index=Kp` → `Observed`. **Kyoto WDC:** out of scope; it has HTML only.
    - **NICT 宇宙天気予報:** **out of scope.** On 2026-10-25, swc.nict.go.jp offered only HTML pages (forecast / alert pages) and no documented machine-readable feed. The settings page lists NICT as 「機械可読の配信なし(未対応)」 with a link.
    - **OpenWeatherMap (optional, key):** `GET {base}/data/2.5/weather?lat=&lon=&appid=&units=metric` → `Forecast` class (model data). The key comes from env `OWM_API_KEY` (config `openweathermap_api_key_env`).
    - **WMM:** the `world_magnetic_model` crate, computed locally. No coefficients are embedded by hand.

    - Every reading keeps `source`, `class` and `at_ms`.
    - `missing` lists enabled sources whose last fetch failed.
    - Overall: `unavailable = true` (「外的要因: 取得できず」) when every enabled external source has no fresh reading. The last values and their times are still shown.

1. **The guard sends something it must not, or sends when it must not.** Check that:

- **JMA 雷・降水ナウキャスト** (PNG tiles only), **NICT 宇宙天気予報** (no machine-readable feed found on 2026-10-25), **Kyoto WDC** (HTML only), and **GNSS DOP prediction from CelesTrak TLE** (SGP4 + almanac too large for v1). Dst index.
- Editing API keys in the UI (config / env only), storing keys encrypted in the DB, and the Open-Meteo commercial contract itself.
- A decision-record replay viewer in the UI, a pre-flight ブリーフィング external-risk list (the summary chip and the settings page show the same data), and voice read-out (spec §10).
- LLM-written alert summaries pushed without an operator question (the AI panel shows a local guard item instead).
- Using the vehicle's battery temperature / `SCALED_PRESSURE` as factors.
- Threshold calibration from real-flight logs. It happens when such logs exist (spec §8); v1 defaults come from the synthetic tests plus scratch SITL.

Mission-planner conventions decided on 2026-10-15 for RGCS:
- Altitude input is preceded by a frame combo box (Rel / Abs / Ter = MAV_FRAME_GLOBAL_RELATIVE_ALT / GLOBAL / GLOBAL_TERRAIN_ALT); mission has a default frame; mixed frames and Ter-without-terrain raise warnings.
- Selection: Shift+click toggles, Shift+drag rubber-bands (map boxZoom disabled), ⌘/Ctrl+click extends a range in list order; dragging any selected marker moves all.
- Map path: 2D = line-gradient coloured by altitude (cyan low → violet high); 3D = terrain (Terrarium DEM) + a custom WebGL layer (`AirPathLayer`, renderingMode 3d) drawing a true 3D polyline with per-vertex altitude in absolute MercatorCoordinate z (matches fill-extrusion heights on terrain), constant pixel width extruded in the vertex shader with feathered AA edges and a dark casing pass; fill-extrusion slabs were rejected because they render as stairs. Custom-layer rules learned the hard way: use your own VAO, and touch GL state ONLY inside render() (buffer uploads deferred) because MapLibre caches GL state and raster tiles go black otherwise. Vertical posts are thin 2 px lines drawn by the same AirPathLayer (ground → flight altitude) — fill-extrusion pillars were rejected (metre-wide boxes become huge slabs when zoomed in and their tops drift from the line at high altitude). Ground discs + solid thin footprint stay (no dashes: dashed lines look dotted on terrain). Markers use `opacityWhenCovered:'1'`, and in 3D the DOM badges / mid-leg “+” handles are floated to the flight altitude by `floatMarkers()` (screen-space offset = transform.coordinatePoint(mercator, altMeters, pixelMatrix3D) − map.project(ground), refreshed on `move`).
- The map operation guide is behind a "?" toggle next to the 2D/3D control; only add-mode / multi-select status is shown unprompted (user asked for no always-on hint).
- Each list row shows the full `MAV_CMD_*` name at the right in monospace; font shrinks by name length (10/9/8/7 px) instead of wrapping.
- Per-command param forms follow ArduPilot docs (copter mission command list); params a vehicle type ignores are shown disabled with an "unused" tag.
- Elevation profile panel docks at the bottom of the map behind a toggle icon; terrain comes from a `TerrainSampler` that decodes Terrarium z13 tiles directly (works in 2D too), sampled every ~5 m along each leg; `groundElev` is the single hook a DSM replaces.
- MapLibre 4.7.1 gotcha #2: the matrix handed to a custom layer (`transform.mercatorMatrix`) is built BEFORE the terrain centre-elevation translation (`translate(0,0,-elevation)`) that modelViewProjectionMatrix / pixelMatrix3D get, so with terrain a custom layer drifts by `transform.elevation` once the user zooms/pans (elevation is 0 until the first interaction, which is why it looked right at first). AirPathLayer.render() compensates by subtracting `MercatorCoordinate.fromLngLat(center, transform.elevation).z` from the vertex z (folded into the matrix).
- MapLibre 4.7.1 gotcha: call `map.stop()` + `setTerrain()` BEFORE `easeTo()`; enabling terrain mid-animation crashes the render loop (`_updateElevation` on undefined centre) and the map freezes silently.
- Operations map (2026-10-15): 3D uses the same DEM terrain; copters are drawn at AMSL = ground elevation at their take-off point (first trail sample) + relative altitude, with a thin anchor post (`veh-air3d`, a second AirPathLayer) and a ground disc (`veh-ground`), and their DOM markers float via the same `floatMarkers()`. Double-click on a vehicle row toggles follow (state `follow`); a chip on the map shows it, the camera jumps to zoom ≥ 15 then eases linearly once per 1 s tick (skipped while the jump is in flight, `_followJump`), and a manual drag (`dragstart`) ends following. The per-tick marker update must NOT be gated on `map.isStyleLoaded()` (false whenever any tile, incl. DEM, is loading) — use a flag set on `load`.
- Maintenance screen vehicle picture is an abstract hub-and-spoke schematic (controller hexagon + telemetry / GPS-compass / IMU / outputs 1–4 / battery / failsafe nodes on a ring; the active parameter section lights up) instead of a quad photo, because the same screen must serve copter / rover / plane / VTOL.
- `#debug` in the URL hash exposes the component as `window.__rgcs` for CDP-driven checks.

**Why:** These were explicit user requests; the Rust/Tauri build is expected to reproduce them.

**How to apply:** When implementing or extending the mission UI, keep these semantics rather than reverting to Mission Planner defaults. See [[r2s-gcs-design-base-prototype]].
- MapLibre 5.24 gotcha (2026-10-19): `easeTo`/`fitBounds`/`flyTo` over terrain set `_elevationFreeze` but only clear it when `freezeElevation: true` is passed — otherwise the centre elevation stays at its old value (0 m after the 3D switch) until a user drag, and in mountains (Kamikochi ~1,500 m) the camera sits inside the terrain with markers off screen. Pass `KEEP_ELEVATION` (map/mapMode.ts) on every camera animation. Low-elevation test sites (Kumagaya ~30 m) hide this — verify 3D at Kamikochi.
- 3D mission editing (user request 2026-10-19): floating badge / altitude chip drags vertically = altitude only; a draggable ground foot (`.rg-foot`) = lat/lon only; 3D path coloured by climb angle (cyan level → mint → amber 22.5° → red ≥45°, descents violet).
- TAKEOFF (user decision 2026-10-19): ArduCopter ignores NAV_TAKEOFF lat/lon (climbs in place, `ModeAuto::do_takeoff`), so the planner's first click makes T at the vehicle (else mission home) + a WAYPOINT at the click; T is not draggable on the map (altitude drag OK). User had reported "always flies to #2 after takeoff".
- Ops 3D shows the selected vehicle's mission like the planner (display only) and tracks in the air; track length = app setting `map.track_minutes` (minutes, user chose time over distance/points; 0–120, default 10).
- Guided move (user 2026-10-19): one "移動開始" button only — switch to GUIDED if needed, wait for telemetry GUIDED (5 s), then send the target; the UI answers confirm_required itself.
- Selection (user 2026-10-19): Shift = range from the last clicked item (adds), ⌘/Ctrl = toggle one; map Shift-drag = box select (by on-screen badge position). ⌘C/⌘V duplicates after the last selected item.
- Fence / rally (2026-10-19): Mission/Fence/Rally tabs under the nav (remembered); fence = inclusion green / exclusion red polygons + circles, rally = R markers; saved inside the mission plan; written via MAV_MISSION_TYPE_FENCE/RALLY lists (no home slot, mission_type on every frame). ArduPilot facts in [[r2s-gcs-dev-environment]]-era research: fence param1 = vertex count / radius, ~70 fence items, ~46 rally points, rally alt int16 m, FENCE_TYPE bit 2 enables polygons/circles.
- ARC_WAYPOINT (36): long-press + drag on the mid-leg "+"; param1 = arc angle, + clockwise; Copter 4.7+ only — the local SITL (4.7.0-dev, Nov 2025) predates it.

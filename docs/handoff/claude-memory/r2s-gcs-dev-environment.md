- **Rust** was installed 2026-10-16 with rustup (`--no-modify-path`, profile minimal + clippy/rustfmt, target aarch64-unknown-linux-gnu). It is NOT on PATH in the shell: prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. Toolchain is stable (1.99 at install time); `rust-toolchain.toml` pins `stable`.
- **mavlink crate 0.19**: dialect types live at `mavlink::dialects::ardupilotmega::*` (not `mavlink::ardupilotmega`). Generated structs have a `DEFAULT` const (`..HEARTBEAT_DATA::DEFAULT`). Async API: `mavlink::connect_async::<MavMessage>(addr)` → `Box<dyn AsyncMavConnection>` with `recv()/send(&header,&msg)`; address strings `udpin:h:p`, `udpout:h:p`, `tcpout:h:p`, `serial:/dev/x:baud`.
- **ts-rs 12**: `TS_RS_EXPORT_DIR` is set in `.cargo/config.toml` to `apps/rgcs-server/ui/src/shared/api/generated`; bindings are regenerated by `cargo test -p rgcs-core` and are committed (CI diffs them). `u64` fields need `#[ts(type = "number")]` (`+ optional` inside `#[ts(optional_fields)]` structs) or they become `bigint`.
- **UI**: npm only (no pnpm). Scripts: `npm run typecheck`, `npm test -- --run`, `npm run lint` (oxlint), `npm run build`. Vitest needs `afterEach(cleanup)` in `src/test/setup.ts` (no globals). `tsconfig` has `erasableSyntaxOnly`: no constructor parameter properties.
- **SITL without MAVProxy**: `~/github/rtos/ardupilot/build/sitl/bin/arducopter --model + --speedup 1 --defaults Tools/autotest/default_params/copter.parm --home 36.2509,137.6385,1505,0 -I0 -w` listens on TCP 5760 (user 2026-10-19: always start SITL at Kamikochi 上高地 for 3D checks; `scripts/dev.sh` SITL_HOME defaults to it) → `mavlink_url = "tcp:127.0.0.1:5760"`. Launch it with the Bash tool's `run_in_background` (macOS has no `setsid`; a `( … &)` subshell child dies when the shell exits). Streams only start after the 10 s SET_MESSAGE_INTERVAL grace, so wait ~15 s before checking. pymavlink exists only in `~/github/rtos/siyi-mt11-cameracontrol/.venv`.
- **Local run**: `RGCS_CONFIG=<toml> RUST_LOG=info ./target/debug/rgcs-server` with `ui_dir` pointing at `apps/rgcs-server/ui/dist`; check `curl :8000/api/vehicles` and a 3 s Node `WebSocket` frame count. Screenshots: reuse the CDP harness in the scratchpad (`glass/cdp.js`), kill Chrome with `pkill -f remote-debugging-port=9333` before relaunching.
- **Bash tool quirk**: the working directory silently resets between calls ("Environment update" notices); always use absolute paths in scripts and heredocs.

- **E2E / acceptance (2026-10-17)**: `scripts/e2e.sh` builds `ui/dist`, starts `rgcs-server` on :8010 and runs Playwright (`apps/rgcs-server/ui/e2e`); `scripts/e2e.sh --with-sitl` adds the SITL journey. `tests/sitl/accept-m1.sh` (curl) arms/disarms via confirm tokens against `RGCS_URL` (default :8000). SITL's tcp:5760 accepts ONE client: stop the dev server before `--with-sitl`. Playwright browsers are cached under `~/Library/Caches/ms-playwright`; the Claude Chrome extension is usually not connected, so manual UI checks run as throwaway Playwright scripts in the scratchpad (import from `<ui>/node_modules/@playwright/test/index.mjs`, use `exact: true` for ARM vs DISARM).
- **ts-rs in rgcs-server**: `Me`, `Health`, `AppSettings` are exported by `cargo test -p rgcs-server` (not only rgcs-core).

**Why:** these cost real time to rediscover (dialect path, bigint bindings, SITL dying, cwd resets).

**How to apply:** follow the above before building or testing; see [[r2s-gcs-deployment-and-camera]] for the product decisions and `docs/plan/implementation-plan.md` for what comes next (M1 week 2: SQLite store, login, command queue with confirm tokens).

- The global `~/.gitconfig` rule rewriting `https://github.com/` → `git@github.com:` was removed on 2026-10-17 at the user's request (backup: `~/.gitconfig.bak-20261017`) so Claude Code plugin/marketplace installs clone over plain HTTPS. The reverse rule (`git@github.com:` → `https://github.com/`) is still present. Repos with HTTPS origins now push over HTTPS; the `gh` token was invalid at that time, so `gh auth login` may be needed before pushing. The default `Host github.com` SSH key (`id_ed25519_rtos`) is passphrase-protected and not in any agent.
- **Dev stack launcher**: `scripts/dev.sh` (added 2026-10-17) starts SITL + `rgcs-server` (RGCS_CONFIG=`.dev/config.toml`) + Vite on 127.0.0.1:5173 and refuses to start if :8000 is busy. A `./target/debug/rgcs-server` from an earlier session often lingers on :8000 (`lsof -nP -iTCP:8000 -sTCP:LISTEN`); confirm its cwd is this repo before killing. API calls from curl need `-H 'X-Requested-With: rgcs'` (CSRF guard) and a cookie from `POST /api/auth/login` (`admin`/`admin` dev account) or `/api/vehicles` returns 401.

- UI has no Prettier/formatter config; code is hand-formatted (single quotes, no semicolons, long lines). Never run `npx prettier` on existing files (defaults rewrite them to double quotes + semicolons). Learned 2026-10-18 (P7).
- Multi-vehicle SITL (2026-10-19, user wants 3): `scripts/dev.sh --sitl 3 --siyi-sim --video` starts 3 SITLs (SYSID 1..3, homes 100 m apart at Kamikochi) → `scripts/mav-relay.py` (udp 14550 → server udpin 14551, broadcasts back). Needed because rust-mavlink udpin replies only to the last peer. State in .dev/sitl/N, logs .dev/sitl-N.log.

ArduPilot for SITL (2026-10-20): `~/github/rtos/ardupilot` is the user's fork checkout (rtos-org, local changes, leave it alone). Upstream master is a detached worktree at `~/github/rtos/ardupilot-latest` (Copter 4.7-dev, has NAV_ARC_WAYPOINT); dev.sh prefers it when built. Build with the fork's venv for empy: `PY=~/github/rtos/ardupilot/sitl-env/bin/python3; $PY ./waf configure --board sitl && $PY ./waf copter` (~7 min). Submodule init with `--reference` fails on pymavlink; plain `git submodule update --init --recursive` works. To update: `git -C ~/github/rtos/ardupilot fetch upstream master && git -C ~/github/rtos/ardupilot-latest checkout --detach upstream/master`, then rebuild.

- Four airframes (2026-10-22): `scripts/dev.sh --sitl 1 --quadplane --plane --rover --siyi-sim --video` → SYSID 1 copter, 2 QuadPlane, 3 plain plane (models/plane.parm), 4 rover. `ardurover` was built in ardupilot-latest with `~/github/rtos/ardupilot/sitl-env/bin/python3 ./waf rover` (plain `./waf` fails: empy missing). A QuadPlane's HEARTBEAT is FIXED_WING; RGCS tells it apart via EXTENDED_SYS_STATE.vtol_state (ArduCopter reports MC too, so only planes count).
